# F0 — Cimientos del Entorno

> [!info] Objetivo
> **Eliminar bloqueos y fijar el andamiaje.** Esta fase no produce funcionalidad del
> sistema: produce las condiciones para que todo lo demás sea posible.

---

## 1. Duración

| Dedicación | Duración |
|---|---|
| 8 h/semana | ~1 semana |
| 15 h/semana | ~3 días |
| Tiempo completo | 2 días |

---

## 2. Tareas

### 2.1 Cerrar los bloqueos técnicos del entorno

```bash
# ❌ FALTA (bloqueante)
sudo apt install php8.3-bcmath php8.3-gd
sudo systemctl restart php8.3-fpm

# ✅ Verificación
php -m | grep -E '^(bcmath|gd|pdo_pgsql|mbstring|intl|sodium|zip|openssl|curl)$'
php -r 'echo bcadd("150000.00", "0.01"), PHP_EOL;'
```

| Extensión | Estado al inicio | Acción |
|---|---|---|
| `bcmath` | ❌ Falta | `apt install php8.3-bcmath` — **bloqueante** |
| `gd` | ❌ Falta | `apt install php8.3-gd` — necesario para fotos |
| `pdo_pgsql` | ✅ | — |
| `mbstring` | ✅ | — |
| `intl` | ✅ | — |
| `sodium` | ✅ | — |
| `redis` | ❌ Falta | **No se instala**: no se usa Redis (ADR-0009) |

### 2.2 Verificar la matriz de versiones

**No se fija ninguna versión hasta confirmarla.** El comando:

```bash
composer show --all laravel/framework | head -20
composer show --all filament/filament | head -20
composer require --dry-run laravel/framework filament/filament
```

**Resultado esperado:** la resolución de dependencias no debe tener conflictos.

**Documento a actualizar:** [[00.03 Stack, Versiones y Dependencias]] con las versiones
exactas verificadas.

| Paquete | Versión a verificar | Criterio |
|---|---|---|
| `laravel/framework` | 11.x o 12.x | La que soporte la versión de Filament elegida |
| `filament/filament` | 3.x | La que soporte la versión de Laravel elegida |
| `pestphp/pest` | 3.x | Compatible con Pest 3 |
| `larastan/larastan` | 3.x | Soporta la versión de Laravel |
| `qossmic/deptrac` | 2.x | — |
| `spatie/laravel-permission` | 6.x | Compatible con la versión de Laravel |

### 2.3 Crear el repositorio

```bash
# GitHub: crear el repositorio PRIVADO
gh repo create sistema-cai --private --description "Sistema de gestión del Centro de Atención Inclusiva"

# Local
git init -b main
git remote add origin git@github.com:<org>/sistema-cai.git
```

**Configuración de `main` protegida** (en GitHub):

| Regla | Valor |
|---|---|
| Branch name pattern | `main` |
| Require a pull request before merging | ✅ |
| Require approvals | 1 (el propio dev, por auto-revisión) |
| Require status checks to pass | ✅ `quality` |
| Require conversation resolution | ✅ |
| `Do not allow bypassing the above settings` | ✅ **Activado** |

### 2.4 Escribir los ADRs

En esta fase se escriben **al menos** los tres ADRs que fijan lo decidido:

| ADR | Decisión |
|---|---|
| [[ADR-0001 Monolito Modular en Paquetes]] | Paquetes Composer por dominio |
| [[ADR-0002 Schema por Módulo en PostgreSQL]] | Un schema por módulo con `search_path` |
| [[ADR-0003 Expand-Contract y Feature Flags]] | Compatibilidad de esquema y kill switches |
| [[ADR-0004 Trunk-based con Tags SemVer]] | Flujo de trabajo y versionado |
| [[ADR-0005 Release por Symlink]] | Despliegue |
| [[ADR-0008 Stack Laravel Filament PostgreSQL]] | Stack |

> [!important] Los ADRs se escriben **antes** de implementar
> Es más barato cambiar un ADR (un documento) que deshacer una implementación de 3
> semanas.

### 2.5 Escribir el borrador del runbook

```bash
touch docs/RUNBOOK.md
```

Estructura inicial (se completa en F8):

```markdown
# Runbook del Sistema CAI

## Comandos frecuentes
## Deploy
## Rollback
## Backups
## Verificación
## Incidentes
```

### 2.6 Preparar el servidor del centro (en paralelo)

Si el servidor ya está disponible, dejar listo:

- [ ] Ubuntu Server 24.04 LTS instalado
- [ ] IP fija asignada
- [ ] UPS conectado y tested
- [ ] Disco con partición `/srv` de 200 GB
- [ ] Usuario `cai` creado

Ver [[07.03 Instalación del Sistema]].

## 4. Gate de salida

> [!success] Condición para pasar a F1
> - [ ] `ext-bcmath` y `ext-gd` instaladas y verificadas
> [ ] Matriz de versiones resuelta sin conflictos y anotada
> [ ] Repositorio privado con `main` protegida
> [ ] Los 6 ADRs escritos
> [ ] Runbook con estructura creada
> [ ] Bóveda de documentación completa y revisada

**Si el gate no se cumple, la fase no termina.** Es preferible una semana más de F0 que
descubrir en F6 que el esquema no es compatible hacia atrás.

---

## 5. Riesgos

| Riesgo | Probabilidad | Impacto | Mitigación |
|---|---|---|---|
| Conflicto entre Laravel y Filament | Media | Alto | Se verifica antes de escribir código; si hay conflicto, se evalúa la versión anterior de Filament |
| La versión de PHP del servidor difiere de la local | Media | Medio | Se define PHP 8.3 como requisito mínimo y se documenta |
| El servidor del centro no está listo en F0 | Alta | Bajo (se pospone a F8) | Se avanza en F0 sin el servidor; el despliegue se hace en F8 |
| Alguien escribe código sin leer los ADRs | Media | Alto | Los ADRs están en la bóveda y se referencian en el checklist de PR |

## 7. Definición de "hecho" para esta fase

La fase F0 está completa cuando un desarrollador que no conoce el proyecto puede:

1. Clonar el repositorio.
2. Leer los 6 ADRs y entender **por qué** el sistema es como es.
3. Instalar las extensiones que faltan y entender por qué.
4. Empezar a trabajar en F1 sin ninguna pregunta bloqueante.
