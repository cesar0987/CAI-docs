# F1 — Andamiaje Técnico y Frontera Modular

> [!info] Objetivo
> Que la CI esté verde con el esqueleto de módulos y **la frontera modular sea
> verificable**, no nominal. En esta fase se demuestra que un PR que cruza fronteras
> **falla**.

---

## 1. Duración

| Dedicación | Duración |
|---|---|
| 8 h/semana | ~2 semanas |
| 15 h/semana | ~1 semana |

---

## 2. Tareas

### 2.1 Crear el proyecto Laravel

```bash
composer create-project laravel/laravel .
```

> [!warning] `.` como destino
> El proyecto se crea en la raíz del repositorio, no en una subcarpeta. Los paquetes van
> en `packages/`, y el host Laravel en la raíz.

### 2.2 Instalar las dependencias de desarrollo

```bash
composer require --dev \
    pestphp/pest \
    pestphp/pest-plugin-laravel \
    larastan/larastan \
    qossmic/deptrac \
    laravel/pint \
    mockery/mockery \
    laravel/tinker

composer require \
    filament/filament \
    spatie/laravel-permission
```

### 2.3 Crear los 9 paquetes

```bash
for pkg in core identity students scheduling care billing documents notifications reporting; do
    mkdir -p packages/${pkg}/src/{Models,Actions,Queries,Contracts,Support,Filament,Events,Listeners}
    mkdir -p packages/${pkg}/database/{migrations,factories,seeders}
    mkdir -p packages/${pkg}/tests/{Unit,Feature,Arch}
    mkdir -p packages/${pkg}/resources/{views,lang}
done
```

`composer.json` de cada paquete:

```json
{

            "Cai\\Students\\": "src/"
```

**ServiceProvider mínimo:**

```php
<?php

declare(strict_types=1);

namespace Cai\Students;

use Illuminate\Support\ServiceProvider;

final class StudentsServiceProvider extends ServiceProvider
{
    public function register(): void
    {
        $this->mergeConfigFrom(__DIR__ . '/../config/students.php', 'students');
    }

    public function boot(): void
    {
        $this->loadMigrationsFrom(__DIR__ . '/../database/migrations');
        $this->loadViewsFrom(__DIR__ . '/../resources/views', 'students');
        $this->loadTranslationsFrom(__DIR__ . '/../resources/lang', 'students');
    }
}
```

> [!note] `core` es diferente
> `packages/core` **no** tiene ServiceProvider propio: contiene código transversal que se
> autoloza por PSR-4 desde el host. No necesita registro.

> [!important] `COMPOSER_MIRROR_PATH_REPOS=1` en producción
> Con esta variable, Composer **copia** los paquetes en `vendor/` en lugar de referenciarlos
> por ruta. Sin ella, cada release dependería de `packages/` en un lugar fijo y el
> release no sería autocontenido. Ver [[06.05 Release y Deploy]].

### 2.6 Crear el comando `cai:migrate` y `cai:db:reset`

```php
// packages/core/src/Console/Commands/MigrateModules.php
final class MigrateModules extends Command
{
    protected $signature = 'cai:migrate {--schema=* : Solo estos schemas}';

    public function handle(): int
    {
        $schemas = $this->option('schema') ?: config('cai.schemas');

        foreach ($schemas as $schema) {
            $this->components->task("Migrando {$schema}", function () use ($schema): bool {
                $this->call('migrate', [
                    '--database'  => $schema,
                    '--path'     => base_path("packages/{$schema}/database/migrations"),
                    '--realpath' => false,
                    '--force'    => true,
                ]);

                return true;
            });
        }

        return self::SUCCESS;
    }
}
```

> [!danger] Gotcha G1 — `migrate:fresh` no borra los schemas de los módulos
> El comando `cai:db:reset` es el que se usa en desarrollo, testing y staging.
> Ver [[06.02 Versionado de Esquema de BD]].

### 2.7 Configurar Deptrac

```yaml
# deptrac.yaml
deptrac:
  paths:
    - ./app
    - ./packages
  exclude_files:
    - '#/.*/(tests?|Fixtures?|database)/#'
  layers:
    - name: Core
      collectors:
        - type: directory
          regex: #/packages/core/.*#

    - name: Identity
      collectors:
        - type: directory
          regex: #/packages/identity/.*#

    - name: Students
      collectors:
        - type: directory
          regex: #/packages/students/.*#

    - name: Scheduling
      collectors:
        - type: directory
          regex: #/packages/scheduling/.*#

    - name: Care
      collectors:
        - type: directory
          regex: #/packages/care/.*#

    - name: Billing
      collectors:
        - type: directory
          regex: #/packages/billing/.*#

    - name: Documents
      collectors:
        - type: directory
          regex: #/packages/documents/.*#

    - name: Notifications
      collectors:
        - type: directory
          regex: #/packages/notifications/.*#

    - name: Reporting
      collectors:
        - type: directory
          regex: #/packages/reporting/.*#

    - name: App
      collectors:
        - type: directory
          regex: #/app/.*#

  ruleset:
    # App solo conoce Core
    App:
      - Core

    # Core no conoce a nadie
    Core: ~

    # Identity solo conoce Core
    Identity:
      - Core

    # Students conoce Core e Identity
    Students:
      - Core
      - Identity

    # Scheduling conoce Core, Identity y Students
    Scheduling:
      - Core
      - Identity
      - Students

    # Care conoce Core, Identity, Students y Scheduling
    Care:
      - Core
      - Identity
      - Students
      - Scheduling

    # Billing conoce Core, Identity y Students
    Billing:
      - Core
      - Identity
      - Students

    # Documents conoce Core, Identity y Students
    Documents:
      - Core
      - Identity
      - Students

    # Notifications conoce Core, Identity, Students, Scheduling y Billing
    Notifications:
      - Core
      - Identity
      - Students
      - Scheduling
      - Billing

    # Reporting conoce todos (es el agregador)
    Reporting:
      - Core
      - Identity
      - Students
      - Scheduling
      - Care
      - Billing
      - Documents
      - Notifications
```

```bash
vendor/bin/deptrac analyse --config-file=deptrac.yaml
```

### 2.8 Configurar la CI

```yaml
# .github/workflows/ci.yml
name: CI

on:
  push:
    branches: [main]
  pull_request:
    branches: [main]

jobs:
  quality:
    runs-on: ubuntu-latest

    services:
      postgres:
        image: postgres:16
        env:
          POSTGRES_USER: cai
          POSTGRES_PASSWORD: cai
          POSTGRES_DB: cai_testing
        ports: ['5432:5432']
        options: >-
          --health-cmd pg_isready
          --health-interval 10s
          --health-timeout 5s
          --health-retries 5

    steps:
      - uses: actions/checkout@v4

      - uses: shivammathur/setup-php@v2
        with:
          php-version: '8.3'
          extensions: bcmath, pdo_pgsql, mbstring, intl, sodium, zip, gd
          coverage: none

      - name: Composer install
        run: composer install --no-interaction --prefer-dist

      - name: Crear schemas de los módulos
        run: php artisan cai:db:reset --env=testing --force

      - name: Verificar formato
        run: vendor/bin/pint --test

      - name: Análisis estático
        run: vendor/bin/larastan analyse --memory-limit=1G

      - name: Fronteras entre módulos
        run: vendor/bin/deptrac analyse --config-file=deptrac.yaml --no-progress

      - name: Arch tests
        run: vendor/bin/pest --testsuite=Arch

      - name: Tests
        run: vendor/bin/pest --coverage --min=70
```

### 2.9 El primer arch test

```php
// packages/core/tests/Arch/ModuleBoundariesTest.php

it('does not use models from the host application', function () {
    expect('Cai\Billing')->not->toUse('App\Models');
});

it('does not use eloquent relations across modules', function () {
    expect('Cai\Billing\Models\Charge')->not->toUse('Cai\Students\Models\Student');
    expect('Cai\Care\Models\ClinicalNote')->not->toUse('Cai\Billing\Models\Payment');
});

it('does not place business logic in filament classes', function () {
    expect('Cai\Billing\Filament')->not->toUse('Illuminate\Support\Facades\DB');
});

it('keeps events free of eloquent models', function () {
    expect('Cai\Students\Events')->not->toUse('Illuminate\Database\Eloquent\Model');
});
```

## 4. Gate de salida

> [!success] Condición para pasar a F2
> - [ ] La CI está **verde** en `main`
> - [ ] Un PR de prueba que viola Deptrac **falla** la CI (demostrado y documentado)
> - [ ] Los 9 paquetes se cargan por Composer y sus ServiceProviders se registran
> - [ ] `cai:db:reset` crea los 8 schemas y las migraciones se aplican
> - [ ] Los arch tests pasan
> - [ ] `composer check` pasa en local

---

## 5. Riesgos

| Riesgo | Mitigación |
|---|---|
| Deptrac genera muchos falsos positivos al principio | Se empieza con una matriz permisiva y se endurece fase a fase |
| Filament 3 y Laravel 12 tienen conflictos | Se verifica en F0; si hay conflicto, se usa Laravel 11 |
| El `path` repository de Composer no funciona en algunos entornos | Se documenta `COMPOSER_MIRROR_PATH_REPOS=1` para CI y producción |
| El host `app/` se usa para todo por inercia | El arch test que prohíbe `App\Models` desde los paquetes |
