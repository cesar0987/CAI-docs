# Identidad, Roles y Sesiones

**Schema:** `identity` · **Paquete:** `cai/identity`

---

## 1. Tablas

| Tabla | Propósito | Notas |
|---|---|---|
| `users` | Usuarios del sistema | Un profesional puede no tener usuario (trabaja en planillas); un usuario puede no ser profesional |
| `roles` | Roles | 7 roles de dominio + roles técnicos |
| `permissions` | Permisos granulares | Formato `<módulo>.<recurso>.<acción>` |
| `model_has_roles` | Asignación usuario↔rol | Polimórfico (para extensibilidad) |
| `model_has_permissions` | Permisos directos | Excepcionales; se auditan |
| `role_has_permissions` | Permisos por rol | Tabla principal |
| `settings` | Configuración del centro | Clave/valor tipado |
| `feature_flags` | Interruptores de funcionalidad | Kill switches |
| `audit_events` | Auditoría de operaciones | **Append-only** |
| `security_events` | Eventos de seguridad | Grants concedidos/revocados, accesos denegados, cambios de rol |

---

## 2. `users`

```sql
CREATE TABLE identity.users (
    id              BIGSERIAL PRIMARY KEY,
    name            VARCHAR(150) NOT NULL,
    email           VARCHAR(254) NOT NULL UNIQUE,
    email_verified_at TIMESTAMPTZ,
    password        VARCHAR(255) NOT NULL,
    remember_token  VARCHAR(100),
    status          VARCHAR(20) NOT NULL DEFAULT 'active',
    last_login_at   TIMESTAMPTZ,
    failed_attempts SMALLINT NOT NULL DEFAULT 0,
    locked_until    TIMESTAMPTZ,
    mfa_secret      VARCHAR(255),
    mfa_enabled_at  TIMESTAMPTZ,
    password_changed_at TIMESTAMPTZ,
    created_at      TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    updated_at      TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    deleted_at      TIMESTAMPTZ,

    CONSTRAINT users_status_check
        CHECK (status IN ('active', 'inactive', 'suspended'))
);
```

**Decisiones:**
- **Email como identificador de login.** El centro no tiene otra identidad natural.
- **`status` en vez de borrado.** Un usuario desactivado conserva su historial (notas
  que escribió, pagos que registró). **Nunca se elimina un usuario.**
- **`failed_attempts` y `locked_until`** permiten el bloqueo por intentos fallidos sin
  depender de la caché (funciona aunque Redis no exista).
- **`mfa_secret`** separado: se puede exigir MFA a un subconjunto de usuarios.
- **No hay `phone`**: el teléfono del personal es dato de contacto del profesional, que
  vive en `scheduling.professionals`, no en la cuenta de acceso.

## 3. Roles

| Código | Nombre | Descripción |
|---|---|---|
| `direccion` | Dirección | Supervisión integral |
| `coordinacion` | Coordinación | Coordinación de profesionales y agenda |
| `secretaria` | Secretaría | Fichas, matrículas, agenda, documentación |
| `profesional` | Profesional | Atención y documentación clínica |
| `finanzas` | Administración Financiera | Cobros, pagos, caja |
| `recepcion` | Recepción | Agenda del día, contacto, retiros |
| `admin_tecnico` | Administración Técnica | Usuarios, configuración, mantenimiento |

**Relación usuario↔rol:** un usuario tiene **exactamente un rol principal**
(recomendación). Puede tener roles secundarios de forma excepcional y auditada (p. ej.
Coordinación + Profesional). Ver RN-100.

**Tabla `roles`:**

```sql
CREATE TABLE identity.roles (
    id          BIGSERIAL PRIMARY KEY,
    name        VARCHAR(60) NOT NULL UNIQUE,
    label       VARCHAR(120) NOT NULL,
    description TEXT,
    created_at  TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    updated_at  TIMESTAMPTZ NOT NULL DEFAULT NOW()
);
```

## 4. Permisos

```sql
CREATE TABLE identity.permissions (
    id          BIGSERIAL PRIMARY KEY,
    name        VARCHAR(120) NOT NULL UNIQUE,
    label       VARCHAR(180) NOT NULL,
    module      VARCHAR(40) NOT NULL,
    is_sensitive BOOLEAN NOT NULL DEFAULT FALSE,
    created_at  TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    updated_at  TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

CREATE TABLE identity.role_has_permissions (
    role_id       BIGINT NOT NULL REFERENCES identity.roles(id) ON DELETE CASCADE,
    permission_id BIGINT NOT NULL REFERENCES identity.permissions(id) ON DELETE CASCADE,
    PRIMARY KEY (role_id, permission_id)
);
```

**`is_sensitive`** marca los permisos que tocan datos clínicos o financieros. Sirve para:
- Generar el reporte de permisos sensibles activos (revisión trimestral).
- Excluirlos de los roles "de confianza mínima".

**Catálogo completo de permisos:** ver [[04.02 Matriz de Permisos por Rol]].

## 5. `settings`

```sql
CREATE TABLE identity.settings (
    key         VARCHAR(120) PRIMARY KEY,
    value       JSONB NOT NULL,
    type        VARCHAR(20) NOT NULL DEFAULT 'string',
    group_name  VARCHAR(40) NOT NULL DEFAULT 'general',
    is_public   BOOLEAN NOT NULL DEFAULT FALSE,
    description VARCHAR(255),
    updated_by  BIGINT REFERENCES identity.users(id),
    updated_at  TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

CREATE INDEX settings_group_index ON identity.settings (group_name);
```

**Grupos previstos:**

| Grupo | Claves de ejemplo |
|---|---|
| `centro` | `centro.nombre`, `centro.ruc`, `centro.direccion`, `centro.telefono`, `centro.logo_path` |
| `facturacion` | `facturacion.moneda` (`PYG`), `facturacion.recibo_pie`, `facturacion.vigencia_recibo` |
| `seguridad` | `seguridad.sesion_minutos`, `seguridad.intentos_max`, `seguridad.bloqueo_minutos` |
| `atencion` | `atencion.hora_inicio`, `atencion.hora_fin`, `atencion.dias_habiles` |
| `conservacion` | `conservacion.notas_clinicas_anios`, `conservacion.documentos_anios` |

**Claves de ejemplo:**

```json
{
  "centro.nombre": "Centro de Atención Inclusiva",
  "centro.ruc": "XXXXXXXX-X",
  "facturacion.moneda": "PYG",
  "facturacion.recibo_pie": "Recibo interno de cobro. No constituye comprobante fiscal."
}
```

> [!important] El pie del recibo
> La clave `facturacion.recibo_pie` existe para poder poner "no constituye comprobante
> fiscal" en el recibo mientras P5 no se resuelve. Ver
> [[01.07 Preguntas Abiertas y Decisiones Pendientes]].

## 6. `feature_flags` (kill switches)

```sql
CREATE TABLE identity.feature_flags (
    key          VARCHAR(80) PRIMARY KEY,
    description  VARCHAR(255) NOT NULL,
    is_enabled   BOOLEAN NOT NULL DEFAULT FALSE,
    scope        VARCHAR(30) NOT NULL DEFAULT 'module',
    updated_by   BIGINT REFERENCES identity.users(id),
    updated_at   TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    created_at   TIMESTAMPTZ NOT NULL DEFAULT NOW(),

    CONSTRAINT feature_flags_scope_check
        CHECK (scope IN ('module', 'feature', 'experiment'))
);
```

**Flags previstos:**

| Key | Ámbito | Función |
|---|---|---|
| `module.billing` | módulo | Apaga todo el módulo de facturación |
| `module.care` | módulo | Apaga el área clínica (retención de datos, no borrado) |
| `module.reporting` | módulo | Apaga los reportes pesados |
| `module.notifications` | módulo | Corta el envío de avisos |
| `feature.clinical_grants` | funcionalidad | Impide conceder nuevos grants |
| `feature.auto_charge_generation` | funcionalidad | Detiene la generación automática de cargos |
| `feature.portal_families` | experimento | Portal de familias (etapa 2) |

**Comportamiento cuando un módulo está apagado:**
- Sus rutas devuelven **503** con un mensaje claro ("módulo temporalmente deshabilitado").
- Sus jobs en cola **no se ejecutan**.
- Sus datos **permanecem intactos**.
- La auditoría registra el cambio del flag.

Ver [[06.04 Feature Flags y Kill Switches]].

## 7. `audit_events` (append-only)

```sql
CREATE TABLE identity.audit_events (
    id            BIGSERIAL PRIMARY KEY,
    actor_user_id BIGINT REFERENCES identity.users(id),
    actor_role    VARCHAR(60),
    action        VARCHAR(80) NOT NULL,
    entity_type   VARCHAR(80) NOT NULL,
    entity_id     VARCHAR(120),
    student_id    BIGINT,
    changes       JSONB,
    context       JSONB,
    ip_address    VARCHAR(45),
    user_agent    VARCHAR(255),
    created_at    TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

CREATE INDEX audit_events_actor_index    ON identity.audit_events (actor_user_id, created_at DESC);
CREATE INDEX audit_events_entity_index   ON identity.audit_events (entity_type, entity_id);
CREATE INDEX audit_events_student_index  ON identity.audit_events (student_id, created_at DESC);
CREATE INDEX audit_events_action_index   ON identity.audit_events (action, created_at DESC);
```

**Decisiones:**
- **Sin `updated_at` y sin `deleted_at`**: la tabla es de solo agregado. Nadie la modifica.
- **`changes` es JSONB**: guarda el diff `{ "campo": { "old": ..., "new": ... } }`.
- **`student_id` desnormalizado**: permite buscar "todo lo que le pasó al alumno X" sin
  recorrer todos los tipos de entidad. Se llena en el observer cuando la entidad tiene
  alumno asociado.
- **No hay FK a `students`** porque `audit_events` está en `identity` y `students` depende
  de `identity` (crearía una dependencia circular). Se usa un id sin restricción.

**Acciones auditadas (mínimo):**

| Prefijo | Ejemplos |
|---|---|
| `auth.` | `auth.login`, `auth.login_failed`, `auth.logout`, `auth.password_changed` |
| `user.` | `user.created`, `user.updated`, `user.role_changed`, `user.deactivated` |
| `student.` | `student.created`, `student.updated`, `student.status_changed` |
| `guardian.` | `guardian.attached`, `guardian.detached`, `guardian.updated` |
| `family.` | `family.created`, `family.member_added`, `family.member_transferred` |
| `enrollment.` | `enrollment.created`, `enrollment.paused`, `enrollment.ended` |
| `session.` | `session.created`, `session.cancelled`, `session.rescheduled` |
| `attendance.` | `attendance.recorded`, `attendance.corrected` |
| `care_plan.` | `care_plan.created`, `care_plan.updated`, `care_plan.closed` |
| `clinical_note.` | `clinical_note.created`, `clinical_note.finalized`, `clinical_note.superseded`, **`clinical_note.viewed`** |
| `charge.` | `charge.created`, `charge.voided`, `charge.adjusted` |
| `payment.` | `payment.registered`, `payment.allocated`, `payment.voided` |
| `receipt.` | `receipt.issued`, `receipt.voided` |
| `document.` | `document.uploaded`, **`document.downloaded`**, `document.replaced` |
| `grant.` | `grant.issued`, `grant.revoked`, `grant.expired` |
| `flag.` | `flag.enabled`, `flag.disabled` |
| `export.` | `export.students`, `export.financial` |

> La distinción `*.viewed` / `*.downloaded` marca las **lecturas** de datos sensibles.
> Ver [[04.05 Auditoría de Datos Sensibles]].

## 8. `security_events`

```sql
CREATE TABLE identity.security_events (
    id            BIGSERIAL PRIMARY KEY,
    event_type    VARCHAR(60) NOT NULL,
    severity      VARCHAR(20) NOT NULL DEFAULT 'info',
    user_id       BIGINT REFERENCES identity.users(id),
    student_id    BIGINT,
    resource_type VARCHAR(80),
    resource_id   VARCHAR(120),
    reason        TEXT,
    metadata      JSONB,
    ip_address    VARCHAR(45),
    created_at    TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

CREATE INDEX security_events_type_index    ON identity.security_events (event_type, created_at DESC);
CREATE INDEX security_events_user_index    ON identity.security_events (user_id, created_at DESC);
```

**Tipos de evento:**

| Tipo | Severidad | Cuándo |
|---|---|---|
| `grant.issued` | `warning` | Se concede un acceso excepcional |
| `grant.revoked` | `warning` | Se revoca |
| `grant.expired` | `info` | Vencimiento automático |
| `access.denied` | `warning` | Intento de acceso no autorizado |
| `auth.failed_repeated` | `critical` | Varios intentos fallidos seguidos |
| `role.changed` | `warning` | Cambio de rol de un usuario |
| `mfa.disabled` | `critical` | Se desactiva MFA en una cuenta privilegiada |
| `export.sensitive` | `warning` | Exportación de datos sensibles |
| `password.reset_requested` | `info` | Solicitud de reset |

## 9. Sesiones y seguridad de acceso

| Aspecto | Configuración | Motivo |
|---|---|---|
| Duración de sesión | 480 min (8 h), con cierre por inactividad de 30 min | Turnos de hasta 8 h; los datos clínicos no deben quedar abiertos |
| Cookie `secure` | `true` | Solo HTTPS, incluso en red local |
| Cookie `http_only` | `true` | El token no es accesible desde JavaScript |
| Cookie `same_site` | `lax` | Protección CSRF de base |
| Regeneración de sesión | Al iniciar sesión y al cambiar de contraseña | Preventivo de la fijación de sesión |
| Rate limiting login | 5 intentos / 15 min / IP+email | Ver `failed_attempts` |
| Bloqueo temporal | 15 min | Registrado en `security_events` |
| Contraseña mínima | 12 caracteres | Falta `bcrypt` cost factor alto (12) |
| MFA | Obligatorio para `direccion` y `admin_tecnico` | Cuentas privilegiadas |
| Cambio de contraseña forzado | Si `password_changed_at` > 180 días | Política de rotación |

## 11. Observaciones de implementación

| Tema | Recomendación |
|---|---|
| Seeders | Roles, permisos y configuración inicial van en `database/seeders/`. El password del primer usuario **no** se hardcodea: se genera en el install o se pide por consola |
| `spatie/laravel-permission` | Se usa, pero **complementa** a las Policies. Las Policies mandan |
| Recuperación de contraseña | Por email, con token de un solo uso y expiración de 60 min |
| Enumeración de usuarios | El login responde igual exista o no el email (evita enumeración) |
| Primer ingreso | Forzar cambio de contraseña y MFA si el rol lo exige |
