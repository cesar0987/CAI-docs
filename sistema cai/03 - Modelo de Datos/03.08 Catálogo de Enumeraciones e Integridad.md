# Catálogo de Enumeraciones e Integridad

Referencia única de todos los valores permitidos en el sistema. **Cualquier columna con
conjunto cerrado de valores tiene su `CHECK` en la base y su enum en PHP.** Si un valor
nuevo aparece en la UI y no está acá, es un bug.

## 2. Implementación de los enums

```php
namespace Cai\Students\Enums;

enum StudentStatus: string
{
    case Active    = 'active';
    case Inactive  = 'inactive';
    case Withdrawn = 'withdrawn';

    public function label(): string
    {
        return match ($this) {
            self::Active    => 'Activo',
            self::Inactive  => 'Inactivo',
            self::Withdrawn => 'Baja',
        };
    }

    /** El alumno aparece en los listados operativos. */
    public function isOperational(): bool
    {
        return $this === self::Active;
    }
}
```

**Reglas:**
- Backed enums de string. El valor en DB es exactamente el valor del enum.
- Un método `label()` para la interfaz (en español).
- Métodos de comportamiento donde tenga sentido (`isOperational()`, `allowsCharging()`).
- El cast del modelo: `'status' => StudentStatus::class`.
- **Nunca** un string suelto en el código: siempre el enum.

## 3. Tipos de columna

| Tipo PostgreSQL | Uso | Notas |
|---|---|---|
| `BIGSERIAL` | PK y FK | 19 dígitos. Simple para backups |
| `VARCHAR(n)` | Texto acotado | `n` explícito siempre |
| `TEXT` | Texto libre | Notas, descripciones |
| `CHAR(3)` | Moneda | `PYG` |
| `DATE` | Fechas sin hora | Nacimiento, vencimiento, vigencia |
| `TIMESTAMPTZ` | Fechas con hora y zona | Sesiones, auditoría, pagos. **Siempre** |
| `TIME` | Horarios del día | Reglas de disponibilidad |
| `NUMERIC(14,2)` | Dinero | **Nunca `float`** |
| `NUMERIC(5,2)` | Porcentajes | Descuentos |
| `BOOLEAN` | Verdadero/falso | Flags |
| `JSONB` | Datos estructurados variables | Ajustes de auditoría, metadatos |
| `CHAR(64)` | Hash SHA-256 | Documentos |
| `SMALLINT` | Números chicos | Capacidad, weekdays |
| `INTEGER` | Números | Duraciones, días |

> [!danger] Nunca `float` para dinero
> `NUMERIC` + cast `decimal` + `bcmath`. Un `float` de PHP no puede representar
> `0.10` exactamente y en un saldo acumulado produce diferencias de un guaraní.

## 4. Catálogo de restricciones

### 4.1 CHECK

| Tabla | Restricción |
|---|---|
| `students` | `status IN ('active','inactive','withdrawn')` · `birth_date <= CURRENT_DATE` |
| `guardians` | `status IN ('active','inactive')` |
| `student_guardians` | `valid_until IS NULL OR valid_until >= valid_from` |
| `family_accounts` | `status IN ('active','inactive','closed')` · `currency = 'PYG'` |
| `family_account_members` | `role IN ('titular','dependiente')` · rango de vigencia válido |
| `services` | `default_duration_minutes > 0` · `modality IN (...)` |
| `enrollments` | `status IN (...)` · fechas coherentes |
| `groups` | `capacity > 0` · `max_duration_minutes > 0` |
| `sessions` | `ends_at > starts_at` · `session_type IN (...)` · `status IN (...)` |
| `session_professionals` | `ends_at > starts_at` · `assignment_role IN (...)` |
| `attendance_records` | `status IN ('present','absent','late','excused')` |
| `care_plans` | `status IN (...)` · fechas coherentes |
| `care_goals` | `status IN (...)` |
| `clinical_notes` | `status IN (...)` · `note_type IN (...)` · `status='draft' OR finalized_at IS NOT NULL` · `supersedes_note_id IS NULL OR correction_reason IS NOT NULL` |
| `clinical_note_access_grants` | `length(reason) >= 20` · `expires_at > created_at` |
| `fee_plans` | `amount > 0` · `discount_percent BETWEEN 0 AND 100` |
| `charges` | `amount > 0` · `0 <= amount_paid <= amount` · `status IN (...)` |
| `payments` | `amount > 0` · `status <> 'voided' OR void_reason IS NOT NULL` |
| `payment_allocations` | `amount > 0` |
| `receipts` | `status <> 'voided' OR void_reason IS NOT NULL` |
| `financial_adjustments` | `amount <> 0` · `length(reason) >= 10` |
| `users` | `status IN (...)` |

### 4.2 UNIQUE

| Restricción | Propósito |
|---|---|
| `students.student_code` | Código único |
| `students.document_id` (índice no único) | Búsqueda; puede repetirse (documentos sin CI) |
| `family_accounts.account_code` | Código único |
| `guardians.document_id` (índice) | Búsqueda |
| `services.name` | Nombre único |
| `professionals.user_id` | Un profesional por usuario |
| `session_participants (session_id, student_id)` | No duplicar participantes |
| `attendance_records.participant_id` | Una asistencia por participante |
| `receipts.payment_id` | Un recibo por pago |
| `receipts.receipt_number` | Número único (no se reutiliza) |
| `payment_allocations (payment_id, charge_id)` | Una imputación por cargo y pago |
| `student_guardians (student_id, guardian_id)` | PK compuesta |
| `role_has_permissions (role_id, permission_id)` | PK compuesta |

### 4.3 Índices únicos parciales

```sql
-- Un tutor principal por alumno
CREATE UNIQUE INDEX student_guardians_one_primary
    ON students.student_guardians (student_id)
    WHERE is_primary AND valid_until IS NULL;

-- Un responsable por plan de atención
CREATE UNIQUE INDEX care_plans_one_responsible
    ON care.care_plan_professionals (care_plan_id)
    WHERE role = 'responsible';

-- Un profesional responsable por alumno
CREATE UNIQUE INDEX professional_assignments_one_responsible
    ON scheduling.professional_assignments (student_id)
    WHERE role = 'responsible' AND valid_until IS NULL;

-- Solo un admins de la fila de secuencia por año/prefijo
CREATE UNIQUE INDEX receipt_sequences_year_prefix
    ON billing.receipt_sequences (year, prefix);
```

### 4.4 Restricciones de exclusión (no solapamientos)

| Tabla | Restricción | Garantía |
|---|---|---|
| `family_account_members` | `student_id` + `daterange(valid_from, valid_until)` | Un alumno, una cuenta activa |
| `enrollments` | `student_id` + `service_id` + `daterange(start_date, end_date)` | Una matrícula activa por servicio |
| `session_professionals` | `professional_id` + `tstzrange(starts_at, ends_at)` | Sin sesiones superpuestas |

**Requieren:** `CREATE EXTENSION btree_gist;`

### 4.5 ON DELETE

| Relación | Comportamiento | Motivo |
|---|---|---|
| `student_guardians.student_id` | `CASCADE` | La relación es parte del alumno |
| `student_guardians.guardian_id` | `RESTRICT` | No se puede borrar un tutor con historial |
| `charges.student_id` | `RESTRICT` | No se puede borrar un alumno con deudas |
| `charges.family_account_id` | `RESTRICT` | Idem |
| `payments.family_account_id` | `RESTRICT` | Idem |
| `clinical_notes.student_id` | `RESTRICT` | Idem |
| `clinical_notes.author_user_id` | `RESTRICT` | La autoría no se pierde |
| `session_participants.student_id` | `RESTRICT` | Idem |
| `professional_assignments.*` | `CASCADE` | Relación auxiliar sin valor histórico autónomo |
| `attendance_records.participant_id` | `CASCADE` | Pertenece al participante |
| `payment_allocations.*` | `CASCADE` | Pertenece al pago/cargo |

> [!important] `RESTRICT` es la regla por defecto
> La soft delete evita la mayoría de los borrados. `RESTRICT` protege los casos en que
> alguien intente un `DELETE` directo.

## 5. Reglas de nomenclatura de base de datos

| Elemento | Convención | Ejemplo |
|---|---|---|
| Tablas | `snake_case` plural | `session_participants` |
| Columnas | `snake_case` singular | `family_account_id` |
| PK | `id` | `id` |
| FK | `<tabla_singular>_id` | `student_id` |
| Timestamps | `created_at`, `updated_at`, `deleted_at` | |
| Booleano | `is_` o `has_` | `is_active`, `has_version` |
| Índices | `idx_<tabla>_<columnas>` o `<tabla>_<columnas>_index` | `charges_account_due_index` |
| Unique parcial | `<tabla>_<regla>_unique` | `student_guardians_one_primary` |
| Exclusión | `<tabla>_<regla>` | `enrollments_no_overlap` |
| CHECK | `<tabla>_<regla>_check` | `charges_amount_check` |
| Trigger | `<tabla>_<acción>` | `session_professionals_sync` |
| Función | `<esquema>_<verbo>` | `billing.check_payment_allocations` |
| Índice GiST | `gix_` o sufijo `_gist` | `sessions_range_index` |

## 6. Checklist de una tabla nueva

Antes de agregar una tabla, verificar:

- [ ] ¿Pertenece al schema del módulo correcto?
- [ ] ¿El módulo es el único dueño? (nadie más escribe)
- [ ] ¿Tiene PK, timestamps y soft delete (si corresponde)?
- [ ] ¿Las columnas con conjunto cerrado tienen `CHECK`?
- [ ] ¿Hay un enum PHP para cada conjunto cerrado?
- [ ] ¿Las FKs tienen `ON DELETE` explícito y correcto?
- [ ] ¿Los índices cubren las consultas de lectura esperadas?
- [ ] ¿Hay una restricción de exclusión si aplica?
- [ ] ¿La migración es compatible con el release anterior? (expand–contract)
- [ ] ¿Hay un test que cubra sus invariantes?
