# Convenciones de Código

> [!important] Principio
> Las convenciones existen para que **cualquier persona** (incluido el dev dentro de 6
> meses) pueda leer el código sin sorpresas. Las que **importan** son las que afectan la
> seguridad o la mantenibilidad; el formato lo resuelve Pint automáticamente.

---

## 1. Idioma

| Elemento | Idioma | Ejemplo |
|---|---|---|
| Código (clases, métodos, variables) | **Inglés** | `CreateStudent`, `familyAccountId` |
| Comentarios de código | **Inglés** | `// Locks the charges to prevent over-allocation` |
| Documentación de código (PHPDoc) | **Inglés** | `/** @return list<StudentSummary> */` |
| Nombres de negocio en el código | Inglés | — |
| Interfaz (lo que ve el usuario) | **Español** | "Registrar asistencia" |
| Mensajes de error de dominio | **Español** | "No existe el alumno {$id}." |
| Documentación del proyecto | **Español** | Esta bóveda |
| Nombres de enum | Inglés | `StudentStatus::Active` |
| Labels de enum (UI) | Español | `->label() => 'Activo'` |

> [!tip] Por qué el código en inglés
> El código es técnico y universal. La documentación del proyecto es para el personal del
> centro, que lee español. La interfaz es la única capa que ve el usuario final.

## 2. Formato automático

**Pint** (PSR-12 + Laravel preset) decide el formato. No hay discusiones.

```bash
# Corregir formato
composer lint:fix      # pint

# Verificar formato (en CI)
composer lint          # pint --test
```

**Configuración (`pint.json`):**

```json
{
  "preset": "laravel",
  "rules": {
    "declare_strict_types": true,
    "ordered_imports": { "sort_algorithm": "alpha" },
    "no_unused_imports": true,
    "single_quote": true,
    "binary_operator_spaces": { "default": "single_space" },
    "not_operator_with_successor_space": true,
    "concat_space": { "spacing": "none" },
    "method_argument_space": { "on_multiline": "ignore" },
    "trailing_comma_in_multiline": { "elements": ["arrays", "arguments", "parameters"] }
  }
}
```

**Reglas adicionales que Pint no aplica:**

| Regla | Detalle |
|---|---|
| `declare(strict_types=1);` | En **todos** los archivos PHP |
| Una clase por archivo |PSR-4 |
| Orden de imports: alphabetiko por namespace | Pint lo hace |
| Imports agrupados: `App\`, `Cai\`, otros, `Illuminate\` | Manual |
| Sin variables globales ni `$_GET` / `$_POST` | — |
| Sin `dd()`, `dump()`, `var_dump()` | `dd()` se usa en desarrollo, se limpia antes del merge |

## 3. Nomenclatura

### 3.1 Clases y métodos

| Elemento | Convención | Ejemplo |
|---|---|---|
| Clase | `PascalCase` | `ClinicalNotePolicy` |
| Interface | `PascalCase` + sustantivo | `StudentDirectory` |
| Trait | `PascalCase` + `Concern` | `AuditableConcern` |
| Enum | `PascalCase` | `AttendanceStatus` |
| Método | `camelCase`, verbo primero | `recordAttendance()` |
| Método estático | `camelCase` | `generate()` |
| Constante de clase | `UPPER_SNAKE_CASE` | `const MAX_ROWS = 500` |
| Constante global | `UPPER_SNAKE_CASE` | `MAX_UPLOAD_MB` |
| Variable | `camelCase` | `$familyAccountId` |
| Colección | `plural` | `$students`, `$charges` |
| Colección de una entidad | `singular` para un elemento, plural para muchos | `$student` / `$students` |
| Propiedad privada | `private readonly` cuando no cambia | `private readonly StudentCodeGenerator $codes` |

### 3.2 Nombres de archivo

| Tipo | Patrón | Ejemplo |
|---|---|---|
| Clase | `ClassName.php` | `CreateStudent.php` |
| Test de Pest | `describe + test` | `tests/Feature/CreateStudentTest.php` |
| Migración | `fecha_hora_schema_accion_tabla` | `2026_03_15_000100_students_create_students_table.php` |
| Config | `snake_case.php` | `students.php` |
| View (Blade) | `kebab-case.blade.php` | `student-form.blade.php` |

### 3.3 Siglas

| Regla | Ejemplo |
|---|---|
| Siglas en PascalCase se capitalizan | `StudentDirectory`, `CarePlan` |
| Siglas dentro de palabras se capitalizan | `PdfExporter`, `ApiClient` |
| Siglas en camelCase se capitalizan | `parseXml`, `getHttpClient` |

## 4. Estructura de un método

**Orden recomendado:**

```php
public function execute(CreateStudentData $data): Student
{
    // 1. Validación de invariantes (fail fast)
    $this->guardAgainstDuplicate($data->documentId);

    // 2. Operación principal
    $student = Student::create([...]);

    // 3. Efectos secundarios (eventos)
    StudentRegistered::dispatch(...);

    // 4. Retorno
    return $student;
}
```

**Reglas:**

| Regla | Detalle |
|---|---|
| Un método hace **una cosa** | Si el nombre necesita "y", divide |
| Validar al principio | Las invariantes se comprueban antes de tocar la base |
| `early return` sobre `else` | Evita anidamiento |
| Los comentarios explican el **por qué** | El *qué* se lee en el código |
| Nada de números mágicos | Constantes con nombre |
| Los `match` sustituyen a los `switch` largos | Más exhaustivo: el compilador obliga a cubrir todos los casos |

```php
// ❌ Mal
public function status(): string
{
    if ($this->status === 'active') {
        return 'Activo';
    } elseif ($this->status === 'inactive') {
        return 'Inactivo';
    } else {
        return 'Baja';
    }
}

// ✅ Bien
public function label(): string
{
    return match ($this->status) {
        self::Active    => 'Activo',
        self::Inactive  => 'Inactivo',
        self::Withdrawn => 'Baja',
    };
}
```

## 5. Tipado y seguridad de tipos

```php
declare(strict_types=1);

// ✅ Siempre tipos de retorno
public function total(Charge $charge): Money

// ✅ Parámetros tipados
public function __construct(private readonly ReceiptNumberGenerator $numbers) {}

// ❌ Nunca
public function total($charge)          // sin tipo
public function total($charge = null)   // sin tipo y con default
```

**Reglas:**

| Regla | Detalle |
|---|---|
| `declare(strict_types=1)` siempre | Obliga a coerción explícita |
| Tipo de retorno **siempre** | Nada de retorno implícito |
| `final` en las clases de dominio | Impide herencia no intencionada |
| `readonly` en propiedades inmutables | `private readonly` |
| Uniones y `enum` en vez de `string` sueltos | `StudentStatus` en vez de `'active'` |
| `never` para funciones que siempre lanzan | `abort()`, `throw` |
| Sin `mixed` salvo en fronteras explícitas | `json_decode()` |

## 6. Manejo de errores

### 6.1 Jerarquía de excepciones

```php
namespace Cai\Core\Exceptions;

abstract class DomainException extends \RuntimeException
{
    abstract public static function code(): string;
}
```

```php
namespace Cai\Students\Exceptions;

final class StudentNotFound extends DomainException
{
    public function __construct(public readonly int $studentId)
    {
        parent::__construct("No existe el alumno {$studentId}.");
    }

    public static function code(): string
    {
        return 'STUDENT_NOT_FOUND';
    }
}
```

**Reglas:**

| Regla | Detalle |
|---|---|
| Las Actions lanzan **excepciones de dominio** | No `ValidationException` de HTTP |
| La UI traduce el código a un mensaje | El código es **estable** (contrato con la API futura) |
| Nunca se capturan excepciones genéricas sin re-lanzar | `catch (\Exception)` está prohibido salvo en el handler global |
| Nunca se traga una excepción | `catch {}` sin acción está prohibido |

```php
// ❌ Prohibido
try {
    $this->doSomething();
} catch (\Exception $e) {
    // ...
}

// ✅ Aceptable
try {
    $this->doSomething();
} catch (ConnectionException $e) {
    report($e);
    throw new TemporaryFailureException(previous: $e);
}
```

### 6.2 Transacciones

```php
// ✅ La Action abre su propia transacción
public function execute(RegisterPaymentData $data): Payment
{
    return DB::connection('billing')->transaction(function () use ($data) {
        // ...
    });
}
```

**Regla:** una transacción por Action. Si se necesitan dos, es que hay dos Actions.

## 7. Consultas a base de datos

### 7.1 Reglas

| Regla | Detalle |
|---|---|
| NUNCA `DB::raw()` en el código de aplicación | Solo en migraciones (índices, triggers) |
| NUNCA `select *` | Columnas explícitas: `->get(['id', 'name'])` |
| Siempre `->paginate()` en listados | Filament lo hace por defecto |
| Relaciones cargadas con `with()` | Evita N+1 |
| Consultas que dependen del usuario: **con scope** | Ver [[04.03 Autorización por Registro]] |
| Sin `->get()` sobre tablas grandes sin filtro | Siempre con `where` o paginación |
| `chunk()` para procesar muchos registros | No cargar 100.000 filas en memoria |

### 7.2 N+1

```php
// ❌ Mal: 1 + N queries
foreach ($students as $student) {
    echo $student->guardians->count();
}

// ✅ Bien: 2 queries
$students = Student::with('guardians')->get();
foreach ($students as $student) {
    echo $student->guardians->count();
}
```

**Herramienta:** el paquete `laravel-debugbar` en local, o un test que cuente queries.

## 8. Seguridad en el código

| Regla | Detalle |
|---|---|
| **Nunca** SQL crudo con datos del usuario | Eloquent y bindings |
| **Nunca** `->raw()` con input | Casting y bindings |
| **Nunca** `@` para silenciar errores | Se manejan explícitamente |
| **Nunca** `eval`, `exec`, `shell_exec` con input | — |
| **Nunca** deserializar datos no confiables | `unserialize()` está prohibido |
| Validar y sanear toda entrada | Reglas de validación de Laravel |
| Escapar toda salida | Blade lo hace; `e()` en strings |
| Autorizar **antes** de actuar | `Gate::authorize()` |
| Los paths de archivos vienen de la BD, no del request | Ver [[02.07 Almacenamiento de Archivos Privados]] |
| Los secretos no van en el código | `.env`, y `.env` no se commitea |
| No registrar datos sensibles | Nada de contraseñas ni contenido clínico en logs |

## 9. Comments y documentación de código

```php
/**
 * Registra un pago y lo imputa a los cargos indicados.
 *
 * La operación completa (pago + imputaciones + recibo + auditoría) se ejecuta
 * en una sola transacción. Si algo falla, no queda nada a medias.
 *
 * @param  RegisterPaymentData  $data  Datos del pago y las imputaciones.
 * @param  array<int, int>  $chargeIds  Cargos a cubrir, en orden de prioridad.
 * @return Payment
 *
 * @throws PaymentExceedsChargeException
 * @throws InvalidAllocationException
 */
```

**Reglas:**

| Regla | Detalle |
|---|---|
| El PHPDoc explica el **contrato**, no la implementación | — |
| `@throws` documenta las excepciones relevantes | Las de dominio |
| Los tipos se declaran en el código, no solo en PHPDoc | El PHPDoc complementa |
| Los comentarios `//` explican el **por qué** | "Por qué" > "Qué" |
| Todo método público de un **contrato** tiene PHPDoc completo | Es API pública |
| Comentarios en inglés | — |

## 10. Filament (capa de interfaz)

**Regla de oro: la lógica de negocio NO vive en Filament.**

```php
// ❌ Prohibido
public static function table(Table $table): Table
{
    return $table
        ->recordActions([
            Action::make('cancelar')
                ->action(function (Session $record) {
                    if ($record->status === 'completed') {
                        throw new \Exception('No se puede');
                    }
                    $record->update(['status' => 'cancelled']);
                    // ... más lógica aquí
                }),
        ]);
}

// ✅ Correcto
public static function table(Table $table): Table
{
    return $table
        ->recordActions([
            Action::make('cancelar')
                ->action(fn (Session $record) => app(CancelSession::class)->execute(
                    new CancelSessionData($record->id, reason: 'Motivo de la cancelación')
                )),
        ]);
}
```

**Otras reglas de Filament:**

| Regla | Detalle |
|---|---|
| Los Resources viven en `packages/<módulo>/src/Filament/` | No en `app/Filament` (salvo transversales) |
| Cada Resource tiene su Policy registrada | — |
| `getEloquentQuery()` siempre aplica el scope | Ver [[04.03 Autorización por Registro]] |
| Los `mutateFormDataBefore*` solo hacen transformaciones de presentación | — |
| Las acciones masivas (bulk) aplican la misma Action | — |
| Las acciones irreversibles piden confirmación | — |
| Los mensajes de validación en español | — |

## 11. Tests

**Reglas:**

| Regla | Detalle |
|---|---|
| Nombre del test = comportamiento esperado | `it_rejects_over_allocation` |
| Un test = un comportamiento | — |
| Nombre en `snake_case` en inglés | — |
| Usar `expect()` de Pest | — |
| Los datos de prueba se crean con factories | No hay datos hardcodeados largos |
| Nada de `sleep()` | Usar `travel()` / `freezeTime()` |
| Nada de assertions sobre detalles internos | Se prueba el comportamiento público |
| Un test que falla debe decir **qué se rompió** | Mensaje claro |

```php
// ✅ Bien
it('rejects an allocation that exceeds the payment amount', function () {
    $payment = Payment::factory()->create(['amount' => 100_000]);
    $charge  = Charge::factory()->create(['amount' => 200_000]);

    expect(fn () => app(AllocatePayment::class)->execute(
        new AllocatePaymentData($payment->id, $charge->id, 150_000)
    ))->toThrow(InvalidAllocationException::class);
});
```

## 12. Arch tests

```php
it('does not use eloquent relations across modules', function () {
    expect('Cai\Billing\Models\Charge')
        ->not->toUse('Cai\Students\Models\Student');
});
```

**Reglas de los arch tests:**

| Regla | Detalle |
|---|---|
| Un arch test por regla | — |
| Nombre que describe la regla | `it_does_not_import_other_modules_models` |
| Deben fallar si alguien rompe la regla | Se prueba una vez que detectan la violación |
| Se ejecutan en la CI | Obligatorio |
