# Importación de Datos Iniciales

> [!danger] La migración de datos es donde más se pierde tiempo
> El sistema puede estar perfecto y, si la planilla de alumnos está mal cargada, la
> primera semana en producción se pierde en corregir datos. **La limpieza de la
> planilla es una tarea del centro, y tiene que empezar antes de que el dev escriba
> una línea de código.**

---

## 1. El principio

> [!important] Lo que se importa y lo que no
> | Se importa | No se importa |
> |---|---|
> | Alumnos activos | **Historial clínico** (nunca) |
> | Tutores y parentescos | Historial de notas de años anteriores |
> | Cuentas familiares | Historial de asistencia si no es fiable |
> | Servicios y grupos | El historial de facturación de otros sistemas |
> | Matrículas activas | Documentos escaneados sueltos (se cargan a mano) |
> | Saldos pendientes (como cargos) | |
> | Professional | |
>
> Las notas clínicas **empiezan con el sistema**. Es una decisión, no una limitación:
> importar notas sin cifrar y sin firma sería meter en el sistema información que
> nunca tuvo la protección que el sistema garantiza.

---

## 2. Las cinco planillas

El importador usa **cinco archivos CSV** separados:

| # | Archivo | Contenido |
|---|---|---|
| 1 | `alumnos.csv` | Un alumno por fila |
| 2 | `tutores.csv` | Un vínculo alumno-tutor por fila |
| 3 | `servicios.csv` | Un servicio por fila |
| 4 | `grupos.csv` | Un grupo por fila |
| 5 | `matriculas.csv` | Una matrícula por fila |

> [!important] Separadas a propósito
> Un solo archivo gigante con todo mezclado es más fácil de producir y más difícil
> de depurar. Con archivos separados, si el grupo está mal cargado, se corrige y se
> reimporta **solo** ese archivo.

## 3. El formato de `alumnos.csv`

### 3.1 Las columnas

| Columna | ¿Obligatoria? | Formato | Ejemplo |
|---|---|---|---|
| `codigo` | No | Texto. Si se omite, se genera | `ALU-0001` |
| `nombres` | ✅ | Texto | `Ana María` |
| `apellidos` | ✅ | Texto | `González Ruiz` |
| `fecha_nacimiento` | Recomendado | `YYYY-MM-DD` | `2015-03-12` |
| `documento` | Recomendado | Texto libre | `1.234.567` |
| `telefono` | No | Texto | `0981 123456` |
| `email` | No | Email | `familia@ejemplo.com` |
| `direccion` | No | Texto | `Calle 12 c/ Av. 34` |
| `barrio` | No | Texto | `Sajonia` |
| `ciudad` | No | Texto | `Asunción` |
| `fecha_ingreso` | Recomendado | `YYYY-MM-DD` | `2024-02-01` |
| `estado` | No | `active` / `inactive` / `withdrawn` | `active` |
| `notas` | No | Texto libre | `Alergia a penicilina` |

### 3.2 Ejemplo

```csv
codigo,nombres,apellidos,fecha_nacimiento,documento,telefono,email,direccion,barrio,ciudad,fecha_ingreso,estado,notas
ALU-0001,Ana María,González Ruiz,2015-03-12,1.234.567,0981123456,familia.gonzalez@ejemplo.com,Calle 12 c/ Av. 34,Sajonia,Asunción,2024-02-01,active,Alergia a penicilina
ALU-0002,Luis Andrés,González Ruiz,2017-07-30,4.567.890,0981123456,familia.gonzalez@ejemplo.com,Calle 12 c/ Av. 34,Sajonia,Asunción,2024-02-01,active,
```

> [!tip] El caso de los dos hermanos
> Fíjate en las dos filas: los dos alumnos tienen el **mismo teléfono y el mismo
> email**, porque son hermanos de la misma familia. Eso es exactamente lo que el
> sistema detecta para agruparlos en la misma cuenta familiar.

### 3.3 El formato de `tutores.csv`

| Columna | ¿Obligatoria? | Formato |
|---|---|---|
| `alumno_codigo` | ✅ | Debe existir en `alumnos.csv` |
| `nombre` | ✅ | Texto |
| `documento` | No | Texto libre |
| `parentesco` | ✅ | `padre`, `madre`, `abuela`, `abuelo`, `tia`, `tio`, `tutor_legal`, `otro` |
| `es_tutor_legal` | No | `1` o `0` |
| `es_contacto_principal` | No | `1` o `0`. **Solo uno por alumno** |
| `puede_retirar` | No | `1` o `0` |
| `recibe_avisos` | No | `1` o `0` |
| `es_emergencia` | No | `1` o `0` |

```csv
alumno_codigo,nombre,documento,parentesco,es_tutor_legal,es_contacto_principal,puede_retirar,recibe_avisos,es_emergencia
ALU-0001,María del Carmen Ruiz,3.456.789,madre,1,1,1,1,1
ALU-0001,Carlos Alberto González,2.345.678,padre,1,0,1,0,0
ALU-0002,María del Carmen Ruiz,3.456.789,madre,1,1,1,1,1
```

> [!important] El mismo tutor en dos filas
> Es **correcto** que "María del Carmen Ruiz" aparezca en las filas de sus dos
> hijos. El importador la reconoce como la misma persona (por documento) y crea
> **un** tutor con dos vínculos. Si el documento está vacío, se la trata como personas
> distintas: por eso el documento del tutor es tan importante.

### 3.4 El formato de `servicios.csv`

| Columna | ¿Obligatoria? | Ejemplo |
|---|---|---|
| `nombre` | ✅ | `Terapia del lenguaje` |
| `descripcion` | No | `Atención de dificultades de comunicación` |
| `duracion_minutos` | ✅ | `45` |
| `modalidad` | ✅ | `individual` o `grupal` |
| `capacidad_maxima` | Si es grupal | `8` |
| `activo` | No | `1` |

### 3.5 El formato de `grupos.csv`

| Columna | ¿Obligatoria? | Ejemplo |
|---|---|---|
| `nombre` | ✅ | `Lenguaje A` |
| `servicio` | ✅ | Debe existir en `servicios.csv` |
| `dias` | ✅ | `1,3` (lunes y miércoles) o `LUN,MAR` |
| `hora_inicio` | ✅ | `10:00` |
| `duracion_minutos` | No | Por defecto, la del servicio |
| `aula` | No | `Sala 1` |
| `capacidad` | No | `8` |

### 3.6 El formato de `matriculas.csv`

| Columna | ¿Obligatoria? | Ejemplo |
|---|---|---|
| `alumno_codigo` | ✅ | `ALU-0001` |
| `servicio` | ✅ | `Terapia del lenguaje` |
| `grupo` | Si el servicio es grupal | `Lenguaje A` |
| `fecha_inicio` | ✅ | `2024-02-01` |
| `fecha_fin` | No | Vacío = sigue activo |
| `profesional` | No | Nombre del profesional |

## 4. Cómo se importa

### 4.1 Siempre con `--dry-run` primero

> [!danger] El `--dry-run` no es opcional
> El primer comando **siempre** es con `--dry-run`. Lee los archivos, valida, y
> **no escribe nada**. Muestra cuántos registros aceptarían y cuáles rechazaría, con
> el motivo.

```bash
# 1. Simulación
php artisan cai:import:students --file=/tmp/alumnos.csv --dry-run

# 2. Revisar el reporte de rechazos
cat /tmp/rechazos.csv

# 3. Importación real
php artisan cai:import:students --file=/tmp/alumnos.csv --report=/tmp/rechazos.csv
```

### 4.2 El orden

```bash
# Siempre en este orden: cada uno depende del anterior
php artisan cai:import:students   --file=/tmp/alumnos.csv    --dry-run
php artisan cai:import:students   --file=/tmp/alumnos.csv

php artisan cai:import:guardians  --file=/tmp/tutores.csv   --dry-run
php artisan cai:import:guardians  --file=/tmp/tutores.csv

php artisan cai:services:seed     --file=/tmp/servicios.csv --dry-run
php artisan cai:services:seed     --file=/tmp/servicios.csv

php artisan cai:import:groups     --file=/tmp/grupos.csv     --dry-run
php artisan cai:import:groups     --file=/tmp/grupos.csv

php artisan cai:import:enrollments --file=/tmp/matriculas.csv --dry-run
php artisan cai:import:enrollments --file=/tmp/matriculas.csv

php artisan cai:users:import      --file=/tmp/usuarios.csv  --dry-run
php artisan cai:users:import      --file=/tmp/usuarios.csv
```

> [!danger] El orden importa
> Si se importan las matrículas antes que los servicios, **todas** fallan. Si se
> importan los grupos antes que los servicios, igual. El importador no adivina: cada
> referencia tiene que existir.

### 4.3 La salida esperada

```text
Leyendo /tmp/alumnos.csv...
  Registros leídos:    287
  Aceptados:           284
  Rechazados:            3

Rechazos (detalle en /tmp/rechazos.csv):
  - Fila 45: 'codigo' duplicado en el archivo (ALU-0012)
  - Fila 112: 'fecha_nacimiento' en formato inválido ('12/03/2015')
  - Fila 233: 'nombres' y 'apellidos' obligatorios

Importación completada. 284 alumnos creados.
```

## 5. Los rechazos

### 5.1 El reporte de rechazos

El importador genera un CSV con los registros rechazados y el motivo:

```csv
fila,codigo,nombres,apellidos,motivo
45,ALU-0012,Pedro,Barrios,Codigo duplicado en el archivo
112,ALU-0089,Ana,Lopez,Fecha de nacimiento invalida: 12/03/2015
233,,,Sin nombre ni apellido
```

### 5.2 Cómo trabajar con los rechazos

1. Abrir el reporte.
2. **Corregir el archivo original** (no el reporte: el reporte es de salida).
3. Volver a importar con `--dry-run`.
4. Cuando el reporte esté vacío, importar de verdad.

> [!important] Corregir el archivo, no el reporte
> Si se edita el reporte de rechazos y se vuelve a pasar, el importador **no** lo
> toma como entrada. El reporte es una **salida**, para diagnóstico.

### 5.3 Las causas más comunes

| Causa | Solución |
|---|---|
| Fecha en formato `DD/MM/AAAA` | Convertir a `YYYY-MM-DD` |
| Cédula con puntos o guiones | Se acepta cualquier formato; es texto |
| Cédula repetida | Son gemelos o un duplicado real: **revisar** |
| Nombres con tilde mal codificada | Guardar el CSV en **UTF-8** |
| Punto y coma en vez de coma | Exportar con coma como separador |
| Codificación Latin-1 | Guardar como UTF-8 |

> [!danger] La codificación del CSV
> El error más común de importación: un CSV exportado de Excel en Windows con
> `Latin-1` produce textos rotos (los acentos y la eñe salen con caracteres extraños). La solución es guardar como **CSV UTF-8**.
> En Excel: *Archivo → Guardar como → CSV UTF-8 (delimitado por comas)*.

## 6. La verificación

> [!important] La verificación es obligatoria
> Una importación "sin errores" no significa una importación correcta. Puede haber
> 280 alumnos cuando son 287. **Siempre hay que contar.**

### 6.1 Comparar los conteos

| Fuente | Conteo |
|---|---|
| Planilla original | ______ |
| Alumnos importados | ______ |
| Alumnos activos en el sistema | ______ |
| Diferencia | ______ |

**La diferencia debe ser cero** (o estar explicada: alumnos que no se importaron
porque no assistían, etc.).

### 6.2 Las verificaciones cruzadas

```text
☐ Todos los alumnos tienen al menos un tutor
☐ Todos los alumnos tienen contacto principal
☐ Los hermanos están en la misma cuenta familiar
☐ Todos los alumnos activos tienen al menos una matrícula
☐ Las matrículas grupales tienen grupo asignado
☐ Los saldos pendientes coinciden con la planilla
☐ Los nombres con tilde se ven bien en el panel
☐ Las fechas de nacimiento se interpretaron bien (revisar 5 al azar)
☐ Los teléfonos y emails de los tutores se copiaron bien
```

### 6.3 La prueba de cinco

> [!tip] No verifiques los 287. Verifica cinco.
> Elegir cinco alumnos al azar —uno de cada zona, uno con nombre poco común, uno con hermanos— y abrir su ficha. Si esos cinco están bien, la importación está bien.
> Revisar los 287 a mano no es una verificación: es una lectura.

## 7. Los saldos pendientes

Si las familias deben dinero del período anterior, se importa como **cargos**:

```csv
alumno_codigo,importe,fecha_vencimiento,descripcion
ALU-0001,250000,2024-01-31,Saldo pendiente de diciembre
ALU-0002,250000,2024-01-31,Saldo pendiente de diciembre
```

```bash
php artisan cai:import:charges --file=/tmp/saldos.csv --dry-run
php artisan cai:import:charges --file=/tmp/saldos.csv
```

> [!important] El saldo se importa como cargo, no como "saldo"
> Porque el sistema **no tiene una columna de saldo**. El saldo se calcula a partir
> de los cargos y las imputaciones. Si se importara un "saldo" como una cifra suelta,
> no habría forma de auditarlo ni de mostrar su detalle a la familia.
>
> El cargo importado aparece en el estado de cuenta con su detalle. La familia ve lo
> mismo que antes, pero ahora **auditable**.

## 8. La seguridad de los archivos

> [!danger] Los CSV con datos de menores no se guardan en el repositorio
> | Regla | Detalle |
> |---|---|
> | Nunca en Git | Ni siquiera en un branch |
> | Solo en `/tmp` del servidor | O en un directorio privado |
> | Se borran después | En cuanto termina la importación verificada |
> | Permisos restrictivos | `chmod 600` |
> | Sin envío por email | No se mandan planillas con datos de menores por correo |

```bash
# Preparar el directorio
mkdir -p /tmp/cai-import
chmod 700 /tmp/cai-import
cp alumnos.csv /tmp/cai-import/
chmod 600 /tmp/cai-import/*.csv

# ... importar ...

# Limpiar
shred -u /tmp/cai-import/alumnos.csv
rm -rf /tmp/cai-import
```

> [!important] Por qué `shred` y no `rm`
> `rm` solo borra el enlace: el contenido sigue en el disco hasta que se sobrescribe.
> Con datos de menores, hay que sobrescribir.

## 9. Los usuarios reales

Los usuarios del sistema se importan al final, cuando la matriz de roles está
confirmada:

```csv
nombre,email,rol,telefono
María del Carmen Ruiz,maria.ruiz@centro.local,secretaria,0981123456
Lic. Ana Paredes,ana.paredes@centro.local,profesional,0981654321
```

```bash
php artisan cai:users:import --file=/tmp/usuarios.csv --dry-run
php artisan cai:users:import --file=/tmp/usuarios.csv
```

> [!danger] Las contraseñas
> El importador genera contraseñas **temporales aleatorias**. Cada usuario tiene que
> cambiarla en el primer inicio de sesión. Las contraseñas **no** se distribuyen por
> email: se entregan en persona.

## 10. Planillas: cómo prepararlas

### 10.1 Desde Excel

```text
1. Abrir la planilla
2. Seleccionar el rango de datos (sin encabezados sueltos arriba)
3. Archivo → Guardar como
4. Tipo: "CSV UTF-8 (delimitado por comas)"
5. Nombre: alumnos.csv
```

### 10.2 Las trampas de Excel

| Trampa | Qué hacer |
|---|---|
| Excel convierte `0012` en `12` | Formatear la columna como **Texto** antes de escribir |
| Excel convierte las fechas | Escribir las fechas como `YYYY-MM-DD` en texto |
| Los acentos se pierden | Guardar como UTF-8 |
| El separador es `;` | "CSV UTF-8 (delimitado por comas)" |
| Las celdas combinadas | Descombinarlas: una fila = un registro |
| Filas vacías al final | Eliminarlas |
| Totales al final | Eliminarlos (el importador los rechazaría) |

> [!danger] La trampa del código con cero adelante
> El código `ALU-0012` se mantiene bien porque tiene letras. Pero si algún
> identificador fuera solo numérico (`0012`), Excel lo convierte en `12` y se rompe la
> correspondencia. **Formatear la columna como Texto antes de pegar los datos.**

## 11. El plan de importación

### 11.1 Cronograma

| Momento | Quién | Qué |
|---|---|---|
| 2 semanas antes del go-live | Centro | Preparar y **limpiar** las 5 planillas |
| 1 semana antes | Dev | Revisar las planillas y dar feedback |
| 3 días antes | Dev | Importación en el entorno de pruebas |
| 3 días antes | Dev + Centro | Verificación cruzada y conteos |
| 1 día antes | Dev | Importación en producción |
| Go-live | Todos | Verificación final en vivo |

### 11.2 La regla del "no antes de"

> [!important] No se importa en producción hasta que el entorno de pruebas pasó
> Importar directo en producción es tentador (es un solo paso más) pero elimina la
> única oportunidad de detectar una planilla mal formada **antes** de que el personal
> del centro esté usándolo.
>
> El costo de importar en pruebas primero: un día.
> El costo de importar mal en producción: días de correcciones manuales.
