# Auditoría de Datos Sensibles

> [!important] Para qué sirve
> La auditoría **no previene** el abuso: **lo revela**. Es el mecanismo que permite
> responder la pregunta *"¿alguien accessed the clinical record of a minor without
> authorization?"* con evidencia, y no con suposiciones.

---

## 1. Las tres tablas de trazabilidad

| Tabla | Schema | Qué registra | Quién puede leerla |
|---|---|---|---|
| `audit_events` | `identity` | Toda operación sensible (escritura y lectura) | Dirección, Administración Técnica |
| `security_events` | `identity` | Eventos de seguridad (grants, roles, fallos, MFA) | Dirección, Administración Técnica |
| `document_access_events` | `documents` | Accesos a documentos | Dirección, Administración Técnica |

**¿Por qué tres tablas y no una?**
- `audit_events` tiene **alto volumen** (cada lectura de una nota genera una fila).
- `security_events` tiene **bajo volumen** y **alta severidad**: se revisa en cada reunión
  de Dirección.
- `document_access_events` tiene un **esquema propio** (módulo `documents`) y su volumen
  es intermedio.

Separarlas permite: consultar rápido lo raro, y no mezclar el ruido con lo importante.

## 2. `audit_events` — el registro general

### 2.1 Estructura

```sql
CREATE TABLE identity.audit_events (
    id            BIGSERIAL PRIMARY KEY,
    actor_user_id BIGINT REFERENCES identity.users(id),
    actor_role    VARCHAR(60),
    action        VARCHAR(80) NOT NULL,
    entity_type   VARCHAR(80) NOT NULL,
    entity_id     VARCHAR(120),
    student_id    BIGINT,
    changes       JSONB,
    context       JSONB,
    ip_address    VARCHAR(45),
    user_agent    VARCHAR(255),
    created_at    TIMESTAMPTZ NOT NULL DEFAULT NOW()
);
```

### 2.2 Qué se audita

| Categoría | Acciones |
|---|---|
| **Autenticación** | `auth.login`, `auth.login_failed`, `auth.logout`, `auth.password_changed`, `auth.password_reset_requested` |
| **Usuarios** | `user.created`, `user.updated`, `user.role_changed`, `user.deactivated`, `user.mfa_enabled`, `user.mfa_disabled` |
| **Alumnos** | `student.created`, `student.updated`, `student.status_changed`, `student.deactivated` |
| **Tutores** | `guardian.attached`, `guardian.detached`, `guardian.updated`, `guardian.pickup_verified` |
| **Familias** | `family.created`, `family.member_added`, `family.member_transferred`, `family.member_removed` |
| **Matrículas** | `enrollment.created`, `enrollment.paused`, `enrollment.resumed`, `enrollment.ended` |
| **Agenda** | `session.created`, `session.updated`, `session.cancelled`, `session.rescheduled`, `session.completed` |
| **Asistencia** | `attendance.recorded`, `attendance.corrected` |
| **Clínico** | `care_plan.created`, `care_plan.updated`, `care_plan.closed`, `clinical_note.created`, `clinical_note.finalized`, `clinical_note.superseded`, **`clinical_note.viewed`** |
| **Financiero** | `charge.created`, `charge.voided`, `charge.adjusted`, `payment.registered`, `payment.allocated`, `payment.voided`, `receipt.issued`, `receipt.voided`, `cash_session.opened`, `cash_session.closed` |
| **Documentos** | `document.uploaded`, `document.replaced`, **`document.downloaded`** |
| **Acceso excepcional** | `grant.issued`, `grant.revoked`, `grant.expired` |
| **Configuración** | `flag.enabled`, `flag.disabled`, `settings.updated` |
| **Datos personales** | `export.students`, `export.financial`, `export.reports` |

> [!danger] La distinción `*.viewed` / `*.downloaded`
> Marca las **lecturas** de datos sensibles. Sin ella, la auditoría solo demuestra
> escrituras, y el mayor riesgo del sistema (leer lo que no corresponde) quedaría invisible.

### 2.3 El registro de cambios (`changes`)

```json
{
  "status": { "old": "active", "new": "inactive" },
  "due_date": { "old": "2026-10-01", "new": "2026-11-01" },
  "amount": { "old": "150000.00", "new": "175000.00" }
}
```

**Reglas:**
- Solo se registran los campos **que cambiaron**.
- Los campos sensibles (contraseñas, tokens) **nunca** se registran.
- El contenido de una nota clínica **nunca** se registra en el diff (está cifrado y además
  es clínico).
- Para operaciones de lectura, `changes` es `null` y el detalle va en `context`.

### 2.4 Garantía de escritura

```php
// packages/core/src/Audit/Auditor.php
public function record(string $action, string $entityType, mixed $entityId, array $options = []): void
{
    AuditEvent::create([
        'actor_user_id' => Auth::id(),
        'actor_role'    => Auth::user()?->getRoleNames()->first(),
        'action'        => $action,
        'entity_type'   => $entityType,
        'entity_id'     => (string) $entityId,
        'student_id'    => $options['student_id'] ?? null,
        'changes'       => $options['changes'] ?? null,
        'context'       => $options['context'] ?? null,
        'ip_address'    => request()?->ip(),
        'user_agent'    => Str::limit((string) request()?->userAgent(), 255),
    ]);
}
```

> [!important] La auditoría va en la misma transacción
> `AuditEvent::create()` usa la conexión `identity`. Si la operación de negocio está en
> otra conexión (`billing`), la auditoría **no** se escribiría en la misma transacción.
>
> **Solución en el MVP:** todas las conexiones de módulo apuntan a la **misma base de
> datos**. Por eso, aunque usen conexiones distintas, PostgreSQL las trata como la misma
> transacción si se abre la transacción desde la conexión correcta. Se implementa un
> helper `Audit::withinTransaction()` que abre la transacción en la conexión del módulo y
> escribe la auditoría en la misma. Verificar en F2 con un test de fallo en cascada.

## 3. `security_events` — lo raro y lo importante

### 3.1 Catálogo

| Evento | Severidad | Cuándo se dispara |
|---|---|---|
| `grant.issued` | ⚠️ warning | Se concede acceso excepcional a un dato clínico |
| `grant.revoked` | ⚠️ warning | Se revoca un grant |
| `grant.expired` | ℹ️ info | Vencimiento automático (job diario) |
| `access.denied` | ⚠️ warning | Intento de acceso no autorizado a un recurso sensible |
| `auth.failed_repeated` | 🔴 critical | 5+ intentos fallidos consecutivos |
| `role.changed` | ⚠️ warning | Se asigna o quita un rol |
| `mfa.disabled` | 🔴 critical | Se desactiva MFA en una cuenta privilegiada |
| `mfa.enabled` | ℹ️ info | Se activa MFA |
| `user.deactivated` | ⚠️ warning | Se desactiva un usuario |
| `export.sensitive` | ⚠️ warning | Se exportan datos personales o financieros |
| `password.reset_requested` | ℹ️ info | Solicitud de recuperación |
| `password.changed` | ℹ️ info | Cambio de contraseña |
| `session.revoked` | ℹ️ info | Se revocan sesiones (baja de personal) |
| `flag.changed` | ℹ️ info | Se activa/desactiva un módulo |

### 3.2 Severidad

| Nivel | Significado | Revisión |
|---|---|---|
| `info` | Informativo | Mensual |
| `warning` | Requiere atención | Quincenal |
| `critical` | Requiere acción inmediata | Inmediata |

### 3.3 Estructura

```sql
CREATE TABLE identity.security_events (
    id            BIGSERIAL PRIMARY KEY,
    event_type    VARCHAR(60) NOT NULL,
    severity      VARCHAR(20) NOT NULL DEFAULT 'info',
    user_id       BIGINT REFERENCES identity.users(id),
    student_id    BIGINT,
    resource_type VARCHAR(80),
    resource_id   VARCHAR(120),
    reason        TEXT,
    metadata      JSONB,
    ip_address    VARCHAR(45),
    created_at    TIMESTAMPTZ NOT NULL DEFAULT NOW()
);
```

## 4. `document_access_events` — los archivos

```sql
CREATE TABLE documents.document_access_events (
    id          BIGSERIAL PRIMARY KEY,
    document_id BIGINT NOT NULL REFERENCES documents.documents(id) ON DELETE CASCADE,
    user_id     BIGINT NOT NULL REFERENCES identity.users(id),
    action      VARCHAR(30) NOT NULL,
    reason      TEXT,
    ip_address  VARCHAR(45),
    user_agent  VARCHAR(255),
    created_at  TIMESTAMPTZ NOT NULL DEFAULT NOW()
);
```

| `action` | Cuándo |
|---|---|
| `view_metadata` | Se ve la ficha del documento (sin abrirlo) |
| `preview` | Se abre en el visor |
| `download` | Se descarga el archivo |
| `print` | Se imprime |
| `delete_request` | Se solicita la eliminación |

**Regla:** descargar un documento de categoría **clínica** exige `reason`. El motivo se
guarda.

## 5. Reglas de la auditoría

### 5.1 Lo que NUNCA se audita

| Dato | Motivo |
|---|---|
| Contraseñas (ni hasheadas) | Inútil y peligroso |
| Tokens de recuperación | Permitiría reutilizarlos |
| `APP_KEY` o claves de cifrado | Filtración catastrófica |
| Contenido de notas clínicas | Es clínico; además está cifrado |
| Datos de terceros no relacionados | Minimización |

### 5.2 Lo que SIEMPRE se audita

| Operación | Motivo |
|---|---|
| Toda lectura de dato clínico | El riesgo principal |
| Toda descarga de documento | Filtración de archivos |
| Toda anulación financiera | Manipulación de saldos |
| Todo cambio de rol | Escalada de privilegios |
| Todo grant | Acceso excepcional |
| Toda exportación | Fuga masiva |
| Todo login fallido | Fuerza bruta / sondeo |
| Todo cambio de flag | Kill switch manipulado |

### 5.3 Inmutabilidad

| Medida | Implementación |
|---|---|
| Sin `updated_at` | La tabla no tiene columna de actualización |
| Sin `deleted_at` | No hay borrado lógico |
| Sin `DELETE` en el código | Test que verifica que no hay `delete()` sobre `AuditEvent` |
| Sin permisos de escritura en la UI | No hay acción de Filament para crear/editar/borrar eventos |
| DB sin permiso de borrado | El rol de aplicación no tiene `DELETE` sobre `identity.audit_events` |

> [!tip] Test de inmutabilidad
> ```php
> it('no permite borrar eventos de auditoria', function () {
>     expect(fn () => AuditEvent::query()->delete())->toThrow(QueryException::class);
> });
> ```
> Requiere que el usuario de base de datos de la aplicación no tenga `DELETE` sobre esa
> tabla. Se configura en la F8.

## 6. Consultas de vigilancia

Estas consultas son la base de los reportes mensuales.

### 6.1 Lecturas clínicas por usuario

```sql
SELECT u.name, COUNT(*) AS lecturas, COUNT(DISTINCT a.student_id) AS alumnos
FROM identity.audit_events a
JOIN identity.users u ON u.id = a.actor_user_id
WHERE a.action = 'clinical_note.viewed'
  AND a.created_at >= NOW() - INTERVAL '30 days'
GROUP BY u.name
ORDER BY lecturas DESC;
```

### 6.2 Usuarios que acceden a alumnos no asignados

```sql
-- Señal de alerta: acceso a un alumno sin relación profesional
SELECT a.actor_user_id, u.name, a.student_id, COUNT(*) AS veces, MAX(a.created_at) AS ultima
FROM identity.audit_events a
JOIN identity.users u ON u.id = a.actor_user_id
WHERE a.action = 'clinical_note.viewed'
  AND a.created_at >= NOW() - INTERVAL '30 days'
  AND NOT EXISTS (
      SELECT 1 FROM scheduling.professional_assignments pa
      WHERE pa.student_id = a.student_id
        AND pa.professional_id = u.professional_id
        AND (pa.valid_until IS NULL OR pa.valid_until >= CURRENT_DATE)
  )
GROUP BY a.actor_user_id, u.name, a.student_id
ORDER BY veces DESC;
```

> [!warning] Salvedad
> Esta consulta produce **falsos positivos** legítimos: el autor de la nota, los
> responsables de plan y los titulares de grant no están en `professional_assignments`.
> La consulta real debe excluir esos casos replicating la lógica de la Policy.

### 6.3 Exportaciones

```sql
SELECT u.name, a.action, a.created_at, a.context
FROM identity.audit_events a
JOIN identity.users u ON u.id = a.actor_user_id
WHERE a.action LIKE 'export.%'
  AND a.created_at >= NOW() - INTERVAL '90 days'
ORDER BY a.created_at DESC;
```

### 6.4 Actividad fuera de horario

```sql
SELECT u.name, COUNT(*) AS eventos, MIN(a.created_at) AS primero, MAX(a.created_at) AS ultimo
FROM identity.audit_events a
JOIN identity.users u ON u.id = a.actor_user_id
WHERE a.created_at::time < '07:00:00' AND a.actor_role IN ('finanzas','admin_tecnico')
GROUP BY u.name;
```

## 7. Reportes y alertas

### 7.1 Reporte mensual para Dirección

| # | Métrica | Objetivo |
|---|---|---|
| 1 | Lecturas clínicas por usuario | Verificar la razonabilidad con la carga de trabajo |
| 2 | Accesos denegados | Si hay muchos, puede ser un problema de permisos o un intento |
| 3 | Grants emitidos y su uso real | Un grant sin uso es un permiso que hay que cerrar |
| 4 | Exportaciones realizadas | Volumen y responsable |
| 5 | Anulaciones financieras | Cantidad, importe y motivo |
| 6 | Usuarios inactivos queenumerate | Deben ser 0 |
| 7 | Accesos fuera de horario | Justificables o no |
| 8 | Documentos clínicos descargados | Con su motivo |

### 7.2 Alertas automáticas (F9)

| Alerta | Condición | Severidad |
|---|---|---|
| Grant sin uso | Concedido hace > 3 días y nunca se usó | ℹ️ info |
| Grant vencido aún activo | `expires_at < NOW()` y `revoked_at IS NULL` | ℹ️ info |
| Volumen inusual de lecturas | > 50 lecturas clínicas/hora de un usuario | ⚠️ warning |
| many denied access | > 10 denegaciones en 1 hora | ⚠️ warning |
| Exportación masiva | Exportación de > 100 registros | ⚠️ warning |
| MFA desactivado | Evento `mfa.disabled` en cuenta privilegiada | 🔴 critical |
| Usuario inactivo con sesión activa | Sesión de usuario desactivado | 🔴 critical |

## 8. Retención

| Tabla | Retención | Motivo |
|---|---|---|
| `audit_events` | **5 años** después de la última escritura de ese actor | Trazabilidad del comportamiento |
| `security_events` | **5 años** | Requisito de seguridad |
| `document_access_events` | **3 años** | Trazabilidad de archivos |
| Logs de Nginx | 90 días rotados | Diagnóstico técnico |
| `storage/logs/laravel.log` | 30 días rotados | Diagnóstico técnico |

> [!question] Definir
> Los plazos de retención de auditoría deben coincidir con los plazos legales aplicables.
> **P4** en [[01.07 Preguntas Abiertas y Decisiones Pendientes]] cubre la conservación de
> datos clínicos; los plazos de auditoría se confirman con la misma revisión legal.

## 9. Checklist mensual de auditoría

- [ ] Revisar `security_events` con severidad `warning` y `critical` del mes
- [ ] Ejecutar el reporte de lecturas clínicas y verificar coherencia
- [ ] Ejecutar la consulta de accesos a alumnos no asignados y explicar los positivos
- [ ] Revisar grants: emissions, uso, expiración, revocación
- [ ] Verificar que ningún usuario inactivo tenga sesiones activas
- [ ] Revisar las anulaciones financieras del mes
- [ ] Verificar que las exportaciones fueron justificadas
- [ ] Confirmar que `audit_events` no fue modificada (checksum o `updated_at` ausente)
- [ ] Archivar el reporte en `91 - Actas de Reunión`
