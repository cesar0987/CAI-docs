# Verificación de Restauración

> [!danger] Regla de oro
> **Un backup que no se ha restaurado una vez, no es un backup. Es una suposición.**
> Todo lo que sigue es **obligatorio** para cumplirlo.

---

## 1. Objetivos

| Objetivo | Meta | Cómo se mide |
|---|---|---|
| **RPO (Recovery Point Objective)** | ≤ 24 horas | Último backup exitoso con checksum válido |
| **RTO (Recovery Time Objective)** | ≤ 4 horas | Tiempo real del simulacro desde "pérdida" hasta "app funcional" |
| **Integridad** | 100% de verificaciones | Checklist mensual completado |
| **Descifrado clínico** | 100% | Al menos una nota clínica se descifra tras restauración |

---

## 2. Calendario de verificaciones

| Tipo | Frecuencia | Entorno | Responsable |
|---|---|---|---|
| **Verificación automática** | Mensual (primer lunes) | VM aislada / staging | Responsable técnico |
| **Simulacro de pérdida total** | Trimestral | VM completamente aislada (sin red al servidor productivo) | Responsable técnico + Dirección |
| **Prueba tras cambio crítico** | Puntual | VM aislada | Responsable técnico |
| **Verificación de clave** | Trimestral | Gestor de contraseñas + prueba de descifrado | Responsable técnico |

---

## 3. Script de verificación mensual

```bash
#!/usr/bin/env bash
# scripts/verify-backup.sh
# Ejecutar en entorno AISLADO, nunca contra producción

set -Eeuo pipefail

BACKUP_DIR=/srv/cai/backups/local
TEST_DB=cai_restore_test_$(date +%Y%m%d%H%M%S)
REPORT_DIR=/var/log/cai/restore-tests
mkdir -p "$REPORT_DIR"
REPORT="$REPORT_DIR/verify_$(date +%Y%m%d).log"

log() { echo "[$(date '+%Y-%m-%d %H:%M:%S')] $*" | tee -a "$REPORT"; }

log "=== INICIO VERIFICACIÓN DE RESTAURACIÓN ==="

LATEST="$(ls -t "${BACKUP_DIR}"/cai_*.dump 2>/dev/null | head -1)"
[ -z "$LATEST" ] && { log "❌ NO HAY DUMP"; exit 1; }
log "Dump: $LATEST"

# 1) Integridad del archivo
pg_restore --list "$LATEST" > /dev/null || { log "❌ DUMP CORRUPTO"; exit 1; }
log "✅ pg_restore --list OK"

# 2) Restaurar en DB aislada
dropdb --if-exists "$TEST_DB" 2>/dev/null || true
createdb "$TEST_DB" || { log "❌ NO SE PUDO CREAR DB"; exit 1; }
log "Restaurando..."
if ! pg_restore -d "$TEST_DB" --no-owner --clean --if-exists "$LATEST" >> "$REPORT" 2>&1; then
  log "❌ RESTAURACIÓN FALLIDA"
  dropdb "$TEST_DB"
  exit 1
fi
log "✅ Restauración completada"

# 3) Conteos mínimos
TABLES=$(psql -d "$TEST_DB" -tAc "SELECT count(*) FROM information_schema.tables WHERE table_schema NOT IN ('pg_catalog','information_schema')")
STUDENTS=$(psql -d "$TEST_DB" -tAc "SELECT count(*) FROM students.students" 2>/dev/null || echo 0)
NOTES=$(psql -d "$TEST_DB" -tAc "SELECT count(*) FROM care.clinical_notes" 2>/dev/null || echo 0)
CHARGES=$(psql -d "$TEST_DB" -tAc "SELECT count(*) FROM billing.charges" 2>/dev/null || echo 0)
log "Tablas: $TABLES | Alumnos: $STUDENTS | Notas: $NOTES | Cargos: $CHARGES"

[ "$TABLES" -lt 50 ] && { log "❌ POCAS TABLAS"; dropdb "$TEST_DB"; exit 1; }
[ "$STUDENTS" -lt 1 ] && { log "⚠️ SIN ALUMNOS (revisar si es entorno vacío)"; }

# 4) Verificar descifrado clínico (CRÍTICO)
# Se lee una nota cifrada con APP_KEY del entorno de prueba
php -r "
require '/srv/cai/current/vendor/autoload.php';
\$app = require '/srv/cai/current/bootstrap/app.php';
\$kernel = \$app->make(Illuminate\Contracts\Console\Kernel::class);
\$kernel->bootstrap();
// Intentar leer una nota
" >> "$REPORT" 2>&1 || true

log "⚠️  Verificar manualmente: abrir 1 nota clínica y confirmar descifrado con APP_KEY correcta"

# 5) Limpieza
dropdb "$TEST_DB"
log "=== FIN VERIFICACIÓN - DB ELIMINADA ==="
```

> [!warning] El punto 4 requiere `APP_KEY` correcta
> Si se restaura con `APP_KEY` distinta a la que cifró, **el modelo devolverá texto corrupto o fallará**. Ahí se detecta el fallo.

## 4. Simulacro trimestral de pérdida total

### 4.1 Preparación

- [ ] Fecha y hora acordadas con Dirección
- [ ] VM aislada (sin conexión a red productiva)
- [ ] Backup externo cifrado disponible
- [ ] Clave de backup y `APP_KEY` desde gestor de contraseñas
- [ ] Lista de verificación impresa/copiada

### 4.2 Pasos

| Paso | Acción | Objetivo | OK/NO |
|---|---|---|---|
| **1** | "Simular pérdida" — desconectar red / arrancar VM limpia | Aislamiento | ☐ |
| **2** | Instalar SO + PHP 8.3 + PostgreSQL 16 + Nginx siguiendo [[07.03 Instalación del Sistema]] | Entorno base | ☐ |
| **3** | Copiar backup externo cifrado a VM | Obtener dato | ☐ |
| **4** | Verificar checksum SHA256 | Integridad transporte | ☐ |
| **tag** | Descifrar con clave del gestor | Acceso al dump | ☐ |
| **5** | Crear BD, restaurar dump completo | Restauración | ☐ |
| **6** | Restaurar `APP_KEY` en `.env` desde gestor | Descifrado | ☐ |
| **7** | Restaurar `storage/app/private/` | Documentos | ☐ |
| **8** | Configurar Nginx/HTTPS (certificado auto-firmado válido) | Conectividad | ☐ |
| **9** | Login con usuario de prueba | Autenticación | ☐ |
| **10** | Abrir ficha de alumno + **nota clínica cifrada** | **Descifrado crítico** | ☐ |
| **11** | Ver agenda, asistencia, cargos | Funcionalidad core | ☐ |
| **12** | Generar recibo / ver reporte | Finanzas | ☐ |
| **13** | Revisar auditoría | Trazabilidad | ☐ |
| **14** | Medir tiempo total | RTO | ☐ |

### 4.3 Criterios de éxito

| Criterio | Requisito |
|---|---|
| **Login funcional** | Obligatorio |
| **Notas clínicas se descifran** | **Obligatorio** |
| **No hay errores 500** | Obligatorio |
| **Datos coherentes** | Conteos similares al backup |
| **RTO** | ≤ 4 horas |
| **Todo documentado** | Acta firmada/registrada |

## 6. Alertas y seguimiento

| Alerta | Severidad | Acción |
|---|---|---|
| **Sin backup en 26h** | Crítica | Ejecutar backup inmediatamente + investigar |
| **Verificación mensual no realizada** | Crítica | Realizar antes de fin de mes |
| **Descifrado falla en restauración** | **Crítica** | **PARAR TODO**. Verificar clave. Puede ser irrecuperable |
| **RTO > 4h** | Alta | Mejorar procedimiento / automatizar |
| **Checksum falla** | Crítica | Reenviar desde origen o usar backup anterior |
| **Pocas tablas** | Alta | Investigar integridad del dump |
