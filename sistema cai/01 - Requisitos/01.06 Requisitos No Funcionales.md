# Requisitos No Funcionales

---

## 1. Rendimiento

| ID | Requisito | Objetivo medible | Cómo se verifica |
|---|---|---|---|
| RNF-001 | Tiempo de respuesta de una pantalla de listado | ≤ 1,5 s (p95) con 300 alumnos | Medición en el servidor del centro |
| RNF-002 | Tiempo de respuesta de la ficha de alumno | ≤ 2 s (p95) | Ídem |
| RNF-003 | Registro de asistencia de una sesión grupal (15 alumnos) | ≤ 30 s | Prueba manual cronometrada |
| RNF-004 | Registro de un pago con imputación y recibo | ≤ 10 s | Ídem |
| RNF-005 | Tiempo de carga del panel de Dirección | ≤ 3 s | Ídem |
| RNF-006 | Carga del calendario mensual | ≤ 2 s con 2.000 sesiones en el rango | Ídem |

> **Nota:** los objetivos son holgados a propósito. El riesgo real del sistema **no** es el
> rendimiento: es la indisponibilidad y la corrupción de datos. Ver §5 y §6.

---

## 2. Escalabilidad y capacidad

| ID | Requisito | Objetivo |
|---|---|---|
| RNF-010 | Alumnos soportados sin degradación perceptible | 1.000 (3,3× el tamaño actual) |
| RNF-011 | Usuarios internos simultáneos | 50 |
| RNF-012 | Sesiones almacenadas | 500.000 (≈ 10 años) |
| RNF-013 | Registros de asistencia | 2.000.000 |
| RNF-014 | Notas clínicas | 200.000 |
| RNF-015 | Documentos almacenados | 200 GB |
| RNF-016 | Transacciones de escritura concurrentes | 50/s en pico |

> **Criterio de revisión:** si el crecimiento real se acerca al 70% de cualquiera de estos
> valores, se reevalúa el diseño de consultas y los índices **antes** de necesitar hardware
> más caro.

---

## 3. Seguridad

| ID | Requisito | Verificación |
|---|---|---|
| RNF-020 | Toda operación sensible genera un registro de auditoría | Test automatizado |
| RNF-021 | Las contraseñas se almacenan hasheadas con bcrypt o argon2 | Inspección |
| RNF-022 | El acceso se bloquea tras N intentos fallidos | Test |
| RNF-023 | Los datos clínicos se almacenan cifrados | Inspección + test |
| RNF-024 | Los documentos no son accesibles sin sesión y permiso | Test de URL directa |
| RNF-025 | PostgreSQL no es accesible desde la red pública | Verificación de configuración |
| RNF-026 | Todo el tráfico web usa HTTPS, incluso en red local | Verificación |
| RNF-027 | Las cuentas privilegiadas requieren MFA | Verificación de configuración |
| RNF-028 | Los datos de menores no salen del perímetro del centro sin cifrado | Revisión de configuración de backup externo |

---

## 4. Privacidad

| ID | Requisito | Verificación |
|---|---|---|
| RNF-030 | Solo se recopilan los datos necesarios para prestar el servicio | Revisión de campos |
| RNF-031 | Existe un plazo de conservación definido por tipo de dato | Política escrita |
| RNF-032 | Existe un procedimiento de atención a solicitudes de acceso | Procedimiento escrito |
| RNF-033 | El consentimiento se registra con versión, fecha y evidencia | Test |
| RNF-034 | Los permisos se revisan trimestralmente | Checklist mensual |

---

## 5. Disponibilidad y continuidad

| ID | Requisito | Objetivo |
|---|---|---|
| RNF-040 | Disponibilidad durante el horario de atención (lun–vie, 07:00–20:00) | ≥ 99% |
| RNF-041 | Tolerancia a corte de energía (UPS) | 15 minutos de autonomía |
| RNF-042 | Tiempo de recuperación ante falla del servidor (RTO) | ≤ 4 horas |
| RNF-043 | Pérdida máxima de datos tolerable (RPO) | ≤ 1 hora |
| RNF-044 | El sistema opera sin conexión a internet | Sí, íntegramente |
| RNF-045 | Procedimiento de continuidad si el servidor no está disponible | Documentado y ensayado |

---

## 6. Integridad y consistencia de datos

| ID | Requisito | Verificación |
|---|---|---|
| RNF-050 | No se pierden datos ante una falla a mitad de una operación | Transacciones de base de datos |
| RNF-051 | Las operaciones de dinero son atómicas (pago + imputación + recibo) | Test de excepción |
| RNF-052 | No se puede imputar más de lo que se pagó o de lo que se debe | Restricciones + test |
| RNF-053 | No hay dos sesiones superpuestas para un profesional | Restricción de exclusión en DB |
| RNF-054 | La numeración de recibos no tiene huecos ni duplicados | Test de concurrencia |
| RNF-055 | No se elimina historial (cargos, pagos, notas, documentos) | Sin `DELETE` en el código |
| RNF-056 | Toda migración es compatible con el release anterior | Checklist de PR |
| RNF-057 | Los backups se verifican restaurando, no solo generando | Restore mensual documentado |

---

## 7. Mantenibilidad

| ID | Requisito | Verificación |
|---|---|---|
| RNF-060 | Ningún módulo depende directamente de otro (verificado por CI) | Deptrac en CI |
| RNF-061 | Las capas internas se respetan (verificado por CI) | Arch tests en CI |
| RNF-062 | La lógica de negocio no reside en las clases de Filament | Code review + arch test |
| RNF-063 | Todo el código nuevo tiene cobertura de pruebas para su camino principal | Cobertura mínima 70% en módulos de negocio |
| RNF-064 | El análisis estático no reporta errores | Larastan nivel 5 en CI |
| RNF-065 | El estilo de código es automático | Pint en CI |
| RNF-066 | Todo paquete tiene README con su responsabilidad y sus contratos | Revisión |
| RNF-067 | Las decisiones no obvias están registradas como ADR | Revisión |

---

## 8. Usabilidad

| ID | Requisito | Verificación |
|---|---|---|
| RNF-070 | La interfaz está en español | Revisión |
| RNF-071 | Ninguna acción irreversible se ejecuta sin confirmación | Revisión |
| RNF-072 | Los errores muestran un mensaje accionable, no un código | Revisión |
| RNF-073 | Cada rol tiene un manual escrito | `09 - Manuales del Centro` |
| RNF-074 | Las acciones frecuentes (registrar asistencia, cobrar) son de ≤ 3 pasos | Prueba con usuarios |

## 9. Auditabilidad

|---|---|---|

| RNF-082 | La auditoría es de solo agregado (append-only) | Sin permisos de escritura en la UI |
| RNF-083 | Los accesos a datos clínicos quedan registrados | Test |
