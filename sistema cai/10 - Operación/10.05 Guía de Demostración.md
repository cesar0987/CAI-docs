# Guía de Demostración

> [!danger] Regla de oro
> Todo lo que se muestra acá es **100 % ficticio**. No se exhibe ningún dato real de
> alumnos, familias o profesionales. **No se escriben contraseñas en este documento**
> ni en el repositorio: el operador las ingresa interactivamente.

**Duración sugerida:** 8–10 minutos. **Público:** Dirección / equipo del centro.

---

## 4. Demo extendida — preparar datos ficticios (5 minutos)

Estos comandos **solo escriben datos inventados**. Ejecutarlos una sola vez.

### 4.1 Usuario profesional

```bash
cd ~/Desktop/CAI
php artisan cai:user --email=profesional.demo@ejemplo.test --name="Dra. Demo Ficticia" --role=profesional
```

No pasar `--password`: el comando la pide interactivamente. Guardar la contraseña solo en
el gestor del operador.

### 4.2 Servicio, profesional, inscripción, regla y sesiones

```bash
cat > /tmp/opencode/demo-setup.php <<'PHP'
<?php
$service = Cai\Scheduling\Models\Service::create([
    'name' => 'Terapia de Lenguaje — Demo', 'modality' => 'both',
    'default_duration_minutes' => 60, 'is_active' => true,
]);
$professional = Cai\Scheduling\Models\Professional::create([
    'display_name' => 'Dra. Demo Ficticia', 'specialty' => 'Fonoaudiología', 'status' => 'active',
]);
Cai\Scheduling\Models\AvailabilityRule::create([
    'professional_id' => $professional->id, 'weekday' => now()->dayOfWeek,
    'start_time' => '09:00:00', 'end_time' => '10:00:00', 'valid_from' => now()->toDateString(),
]);
$students = Cai\Students\Models\Student::query()->orderBy('id')->limit(2)->get();
foreach ($students as $student) {
    Cai\Scheduling\Models\Enrollment::create([
        'student_id' => $student->id, 'service_id' => $service->id,
        'start_date' => now()->toDateString(), 'status' => 'active',
    ]);
    Cai\Scheduling\Models\ProfessionalAssignment::create([
        'professional_id' => $professional->id, 'student_id' => $student->id,
        'role' => 'responsible', 'valid_from' => now()->toDateString(),
    ]);
}
$created = app(Cai\Scheduling\Actions\GenerateRecurringSessions::class)->execute(
    new Cai\Scheduling\Data\GenerateRecurringSessionsData(
        serviceId: $service->id, from: now()->startOfWeek()->toImmutable(),
        to: now()->startOfWeek()->addWeek()->toImmutable(), createdBy: null,
    ),
);
foreach (Cai\Scheduling\Models\Session::query()->where('service_id', $service->id)->get() as $session) {
    foreach ($students as $student) {
        Cai\Scheduling\Models\SessionParticipant::create([
            'session_id' => $session->id, 'student_id' => $student->id, 'added_by' => null,
        ]);
    }
}
echo 'Sesiones creadas: '.$created.PHP_EOL;
PHP
php artisan tinker --execute="require '/tmp/opencode/demo-setup.php';"
```

**Resultado esperado:** `Sesiones creadas: 1` y dos participantes (Ana y Bruno).

### 4.4 Nota clínica cifrada

Ingresar con `profesional.demo@ejemplo.test` (sin TOTP, su rol no lo exige) y:

1. `/panel/clinical-notes/create` → elegir Ana, tipo `session`, resumen y contenido ficticio.
2. Verificar que el selector de alumnos **solo muestra los asignados**.
3. En el listado, botón **Finalizar**.
4. Abrir el detalle: se registra `clinical_note.viewed` en auditoría.
5. Volver a abrir la nota: no tiene botón de editar (es inmutable).

Comando para mostrar el cifrado en reposo (sin revelar la clave):

```bash
php artisan tinker --execute="\$n = Cai\Care\Models\ClinicalNote::first(); echo 'en BD: ' . substr(DB::table('clinical_notes')->where('id', \$n->id)->value('content'), 0, 12) . '...'; echo ' al leer: ' . \$n->content;"
```

**Mensaje:** el contenido se guarda cifrado con AES-256-GCM y clave separada; el panel
nunca muestra el contenido en el listado, solo el resumen.

### 4.6 Finanzas: cuenta familiar con dos hermanos

```bash
cat > /tmp/opencode/demo-billing.php <<'PHP'
<?php
$family = Cai\Students\Models\FamilyAccount::query()->orderBy('id')->first();
$student = Cai\Students\Models\Student::query()->orderBy('id')->first();
$user = Cai\Identity\Models\User::query()->orderBy('id')->first();
$charge = Cai\Billing\Models\Charge::create([
    'family_account_id' => $family->id, 'student_id' => $student->id,
    'description' => 'Cuota mensual demo — Terapia de Lenguaje',
    'due_date' => now()->addDays(10)->toDateString(), 'amount' => '300000.00', 'status' => 'pending',
]);
$payment = Cai\Billing\Models\Payment::create([
    'family_account_id' => $family->id, 'amount' => '500000.00', 'paid_at' => now(),
    'method' => 'cash', 'received_by' => $user->id,
]);
Cai\Billing\Models\PaymentAllocation::create([
    'payment_id' => $payment->id, 'charge_id' => $charge->id, 'amount' => '300000.00',
]);
$b = app(Cai\Billing\Queries\FamilyAccountBalance::class)->forFamily($family->id);
echo 'cobrado='.$b->charged.' imputado='.$b->allocated.' saldo='.$b->outstanding.PHP_EOL;
PHP
php artisan tinker --execute="require '/tmp/opencode/demo-billing.php';"
```

**Resultado esperado:** `cobrado=300000.00 imputado=300000.00 saldo=0.00`.

**Mensaje:** la familia pagó una sola vez, el cargo quedó cubierto y el saldo **se calcula**,
nunca se edita. Los 200.000 restantes quedan como anticipo sin imputar: qué hacer con ese
saldo depende de P1/P9, que siguen abiertas (ver [[01.08 Cuestionario para Dirección]]).

## 5. Límites que hay que decir en voz alta

1. **P1 y P2 no están respondidas**: hoy se muestra un cargo manual y cuota fija; no hay
   generación automática por sesión ni redondeo guardado.
2. **P3, P5, P9, P10 y P23 no están respondidas**: no hay descuentos, becas, pago de
   terceros, comprobante fiscal ni umbral de caja validado.
3. **F6 no tiene pantallas de Finanzas todavía**: el saldo se muestra por consulta, no en un
   recurso del panel. Eso viene en el siguiente paso.
4. **No hay facturación electrónica ni portal de familias**: quedan para etapa 2.
5. **PostgreSQL no fue demostrado**: el entorno local es SQLite; los `CHECK`, triggers y
   `search_path` de producción requieren el servidor real.
