# Monitoreo y Mantenimiento

> [!important] Enfoque
> Con un solo servidor y un solo desarrollador part-time, el monitoreo tiene que ser
> **automático y barato**. La estrategia es: **un healthcheck cada 5 minutos + alertas por
> correo + una revisión semanal de 20 minutos**. Nada de plataformas de monitoreo
> externas.

---

## 1. Las tres capas de monitoreo

| Capa | Qué vigila | Herramienta | Frecuencia |
|---|---|---|---|
| **1. Salud** | ¿El sistema responde? | `healthcheck.sh` + cron | Cada 5 min |
| **2. Estado** | ¿Cómo van los recursos? | Script de métricas + correo | Diaria |
| **3. Negocio** | ¿Los datos están consistentes? | Reportes y auditorías | Semanal / mensual |

---

## 2. Capa 1 — Healthcheck

```bash
#!/usr/bin/env bash
# scripts/healthcheck.sh
set -uo pipefail

APP_ROOT=/srv/cai
LOG="/var/log/cai-healthcheck.log"
STATUS_FILE="/tmp/cai-healthcheck.status"
FAILED=0

log() { echo "[$(date +%Y-%m-%d\ %H:%M:%S)] $*" >> "${LOG}"; }

check() {
    local name="$1"; shift
    if "$@" > /dev/null 2>&1; then
        log "OK   ${name}"
    else
        log "FAIL ${name}"
        FAILED=1
    fi
}

# El sitio web responde
check "http" curl -sf -o /dev/null --max-time 10 https://cai.centro.local/login

# La base de datos responde
check "database" sudo -u postgres psql -d cai -c "SELECT 1"

# PHP-FPM está activo
check "php-fpm" systemctl is-active --quiet php8.3-fpm

# Nginx está activo
check "nginx" systemctl is-active --quiet nginx

# La aplicación responde
check "app" bash -c "cd ${APP_ROOT}/current && php artisan cai:healthcheck"

# Disco con espacio
DISK=$(df --output=pcent /srv | tail -1 | tr -dc 0-9)
if [ "${DISK}" -lt 85 ]; then
    log "OK   disk (${DISK}% usado)"
else
    log "FAIL disk (${DISK}% usado)"
    FAILED=1
fi

# Memoria disponible
MEM=$(free | awk '/^Mem:/{printf "%.0f", $7/$2*100}')
if [ "${MEM}" -gt 15 ]; then
    log "OK   memory (${MEM}% libre)"
else
    log "FAIL memory (${MEM}% libre)"
    FAILED=1
fi

# El backup es reciente
LATEST=$(find "${APP_ROOT}/backups/local" -name 'cai_*.dump' -mtime -1 2>/dev/null | head -1)
if [ -n "${LATEST}" ]; then
    log "OK   backup ($(basename "${LATEST}"))"
else
    log "FAIL backup (no hay dump en las últimas 24 h)"
    FAILED=1
fi

# El certificado TLS está por vencer
if echo | openssl s_client -connect 127.0.0.1:443 2>/dev/null \
    | openssl x509 -noout -checkend 2592000 > /dev/null 2>&1; then
    log "OK   tls-certificate"
else
    log "WARN tls-certificate (vence en menos de 30 días)"
fi

# Estado
if [ "${FAILED}" = "0" ]; then
    echo "OK" > "${STATUS_FILE}"
    log "=== HEALTHCHECK GLOBAL: OK ==="
else
    echo "FAIL" > "${STATUS_FILE}"
    log "=== HEALTHCHECK GLOBAL: FAIL ==="
    # Alerta por correo
    /srv/cai/scripts/alert.sh "CAI: healthcheck FALLIDO" \
        "Revisar /var/log/cai-healthcheck.log en el servidor del centro."
fi
```

```cron
# /etc/cron.d/cai-healthcheck
*/5 * * * * root /srv/cai/scripts/healthcheck.sh
```

> [!danger] El healthcheck es la primera línea de defensa
> Si el healthcheck falla 3 veces seguidas (15 minutos), el personal del centro debe ser
> notificado. Sin eso, un sistema caído se descubre cuando alguien llega a pedir la ficha
> de un alumno.

## 3. Capa 2 — Métricas diarias

```bash
#!/usr/bin/env bash
# scripts/daily-metrics.sh
set -uo pipefail

REPORT="/tmp/cai-metrics-$(date +%Y%m%d).txt"

{
echo "=== MÉTRICAS CAI — $(date '+%Y-%m-%d %H:%M') ==="
echo

echo "-- Sistema --"
uptime
free -h
df -h /srv /var
echo

echo "-- PostgreSQL --"
sudo -u postgres psql -d cai -tAc "
    SELECT 'Conexiones activas: ' || count(*) FROM pg_stat_activity WHERE datname='cai';
    SELECT 'Tamaño de la base: ' || pg_size_pretty(pg_database_size('cai'));
    SELECT 'Cache hit ratio: ' || round(100.0*sum(heap_blks_hit)/NULLIF(sum(heap_blks_hit)+sum(heap_blks_read),0),2) || '%'
        FROM pg_statio_user_tables;
"
echo

echo "-- Aplicación --"
cd /srv/cai/current
php artisan cai:healthcheck
echo

echo "-- Errores recientes en el log --"
grep -c "ERROR\|CRITICAL\|EMERGENCY" /srv/cai/shared/storage/logs/laravel.log 2>/dev/null || echo 0
echo

echo "-- Últimos 5 errores --"
grep "ERROR\|CRITICAL" /srv/cai/shared/storage/logs/laravel.log 2>/dev/null | tail -5
echo

echo "-- Backup --"
ls -lt /srv/cai/backups/local/ | head -5
echo

echo "-- Discos --"
ls -lt /mnt/backup-usb/ 2>/dev/null | head -3 || echo "Destino externo no montado"
} > "${REPORT}"

# Enviar por correo
/usr/local/bin/mail -s "CAI: métricas diarias $(date +%Y-%m-%d)" \
    -r "sistema@centro.local" direccion@centro.local < "${REPORT}"

# Conservar 30 días
find /tmp -name 'cai-metrics-*.txt' -mtime +30 -delete
```

```cron
# /etc/cron.d/cai-metrics
30 7 * * * root /srv/cai/scripts/daily-metrics.sh
```

## 4. Alertas

```bash
#!/usr/bin/env bash
# scripts/alert.sh
set -uo pipefail

SUBJECT="$1"
BODY="${2:-Sin detalles}"

# Envío por correo al responsable
/usr/local/bin/mail -s "[ALERTA] ${SUBJECT}" \
    -r "sistema@centro.local" \
    direccion@centro.local admin-tecnico@centro.local <<EOF
${SUBJECT}

${BODY}

Servidor: $(hostname)
Fecha:   $(date '+%Y-%m-%d %H:%M:%S')
EOF

# Además queda en el log
echo "$(date '+%Y-%m-%d %H:%M:%S') ALERTA: ${SUBJECT}" >> /var/log/cai-alerts.log
```

### 4.1 Catálogo de alertas

| # | Condición | Severidad | Quién recibe | Acción |
|---|---|---|---|---|
| A-01 | Healthcheck falla 3 veces seguidas (15 min) | 🔴 Crítica | Dirección + Técnico | Verificar el servidor |
| A-02 | Disco > 85% | 🔴 Crítica | Técnico | Liberar espacio (releases viejos, logs) |
| A-03 | Disco > 95% | 🔴 Crítica | Dirección + Técnico | El sistema puede fallar: liberar espacio urgente |
| A-04 | Sin backup en 26 h | 🔴 Crítica | Técnico | Ejecutar el backup a mano |
| A-05 | Memoria libre < 10% | 🟠 Alta | Técnico | Reiniciar PHP-FPM |
| A-06 | Errores 500 en el log > 20 en 1 h | 🟠 Alta | Técnico | Revisar el log |
| A-07 | Certificado TLS vence en < 15 días | 🟠 Alta | Técnico | Renovar |
| A-08 | PostgreSQL no responde | 🔴 Crítica | Dirección + Técnico | Verificar el servicio |
| A-09 | Backup externo no encontrado | 🟠 Alta | Técnico | Revisar el destino |
| A-10 | Verificación de restore fallida | 🔴 Crítica | Dirección | Investigar el backup |
| A-11 | Grants vencidos pendientes de revisión | ℹ️ Info | Técnico | Revisar |
| A-12 | Sin conexión a internet | ℹ️ Info | — | Ninguna (el sistema funciona) |

> [!important] A-12 es intencional
> La pérdida de internet **no es una alerta del sistema**. El sistema sigue funcionando.
> Alerta solo si además falla el healthcheck.

## 5. Capa 3 — Monitoreo de negocio

### 5.1 Reporte semanal

| Métrica | Query / fuente | Objetivo |
|---|---|---|
| Alumnos activos | `students.students` donde `status = 'active'` | — |
| Sesiones del semana | `scheduling.sessions` | — |
| Tasa de asistencia | `scheduling.attendance_records` | > 80% |
| Cargos generados / impagados | `billing.charges` | — |
| Cobranza del mes | `billing.payments` | Meta del centro |
| Deuda total | Suma de cargos pendientes | — |
| Notas clínicas creadas | `care.clinical_notes` | — |
| Notas en borrador (> 7 días) | `care.clinical_notes` donde `status = 'draft'` | **0** |
| Grants activos | `care.clinical_note_access_grants` | — |
| Usuarios inactivos con sesión | `identity.users` + `sessions` | **0** |

> [!danger] Notas en borrador de más de 7 días
> Una nota clínica en borrador es trabajo clínico **sin finalizar**. Si se acumulan, la
> información de atención del alumno está incompleta. Es el indicador de salud del
> registro clínico más importante.

## 6. Mantenimiento programado

### 6.1 Diario (automático)

| Tarea | Script | Hora |
|---|---|---|
| Healthcheck | `healthcheck.sh` | Cada 5 min |
| Backup de la base | `backup.sh` | 23:00 |
| Backup externo cifrado | `backup-external.sh` | 02:00 |
| Métricas diarias | `daily-metrics.sh` | 07:30 |
| Limpieza de caché de Laravel | `php artisan cache:clear` | 03:00 |
| Revocación de grants vencidos | `php artisan cai:grants:expire` | 04:30 |

### 6.2 Semanal (manual, 20 min)

| # | Tarea | Comando |
|---|---|---|
| 1 | Revisar el log de errores de la semana | `grep ERROR storage/logs/laravel.log` |
| 2 | Revisar las alertas de la semana | `cat /var/log/cai-alerts.log` |
| 3 | Verificar el backup externo | `ls -lt /mnt/backup-usb/` |
| 4 | Revisar el espacio en disco | `df -h /srv` |
| 5 | Revisar los índices sin usar | consulta de `pg_stat_user_indexes` |
| 6 | Revisar los queries lentos | `pg_stat_statements` |
| 7 | Verificar los drafts clínicos | reporte de la §5.1 |
| 8 | Limpiar releases antiguos (si > 8) | `prune-releases.sh` |

### 6.3 Mensual

| # | Tarea | Responsable |
|---|---|---|
| 1 | **Verificación de restauración del backup** | Técnico |
| 2 | Revisión de roles y permisos | Dirección |
| 3 | Revisión de `security_events` | Dirección |
| 4 | Revisión de grants | Técnico |
| 5 | Actualización de seguridad del sistema | Técnico |
| 6 | `composer update` (dependencias) | Técnico |
| 7 | Revisión de la configuración de Nginx/PHP | Técnico |
| 8 | Simulación de rollback de código | Técnico |

### 6.4 Trimestral

| # | Tarea | Responsable |
|---|---|---|
| 1 | **Simulacro de pérdida total del servidor** (3 h) | Técnico + Dirección |
| 2 | Revisión de la matriz de permisos | Dirección |
| 3 | Revisión de la política de retención de datos | Dirección + Legal |
| 4 | Rotación de contraseñas de la base de datos | Técnico |
| 5 | Revisión de los paquetes del sistema (`apt upgrade`) | Técnico |
| 6 | Revisión de la vigencia de los ADRs | Dirección + Técnico |

### 6.5 Anual

| # | Tarea | Responsable |
|---|---|---|
| 1 | Revisión completa de la documentación | Dirección |
| 2 | Revisión de la política de seguridad | Dirección |
| 3 | Renovación del certificado (si es CA interna) | Técnico |
| 4 | Cambio de la contraseña de `APP_KEY` (con plan de re-cifrado) | Técnico |
| 5 | Revisión de las preguntas abiertas | Dirección |

## 7. Actualizaciones del sistema

### 7.1 Actualizaciones de seguridad del SO

```bash
# Ver qué hay disponible
sudo apt update
apt list --upgradable

# Aplicar
sudo apt upgrade -y
sudo reboot    # Si se actualizó el kernel

# Después del reinicio
sudo systemctl status nginx php8.3-fpm postgresql
cd /srv/cai/current && php artisan cai:healthcheck --strict
```

**Regla:** las actualizaciones de seguridad se aplican **dentro de la ventana de
mantenimiento** y con el dev disponible.

### 7.2 Actualización de dependencias de PHP

```bash
cd /srv/cai/releases/nuevo-release
composer update --with-all-dependencies
composer test
```

**Reglas:**

| Dependencia | Riesgo | Procedimiento |
|---|---|---|
| Patch | Bajo | Actualización normal |
| Minor | Medio | PR propio + staging + pruebas |
| **Major** (Laravel, PHP) | Alto | Rama dedicada, PRs pequeños, plan de rollback específico |

### 7.3 Actualización de PostgreSQL

```bash
# Ubuntu gestiona el versionado
sudo apt install postgresql-17   # si se migra de versión

# Migración con pg_upgrade (NO dump/restore para una actualización mayor)
sudo /usr/lib/postgresql/17/bin/pg_upgrade -D /var/lib/postgresql/17/main ...
```

> [!danger] Actualización mayor de PostgreSQL
> Es una operación de riesgo. **Se hace solo en una ventana de mantenimiento amplia, con
> backup verificado y con la posibilidad de volver a la versión anterior.** La decisión de
> hacerlo o no se toma cada 2–3 años, no por urgencia.

## 8. Gestión de logs

### 8.1 Rotación

```bash
# /etc/logrotate.d/cai
/srv/cai/shared/storage/logs/*.log {
    daily
    rotate 30
    compress
    delaycompress
    missingok
    notifempty
    copytruncate
    su www-data adm
}

/var/log/nginx/cai-*.log {
    daily
    rotate 90
    compress
    delaycompress
    missingok
    notifempty
    copytruncate
}

/var/log/cai-*.log {
    weekly
    rotate 12
    compress
    missingok
    notifempty
}
```

### 8.2 Niveles de log

| Ambiente | `LOG_LEVEL` | Qué se registra |
|---|---|---|
| local | `debug` | Todo |
| staging | `info` | Todo excepto debug |
| **producción** | `warning` | Solo advertencias y errores |

> [!tip] Por qué `warning` en producción
> El log en `debug` en producción puede:
> - Contener datos sensibles en los mensajes de error.
> - Crecer descontroladamente (un error por request = 50 MB/día).
> - Exponer consultas SQL con valores.
>
> Los errores sí se registran completos, pero **sin contenido clínico**.

### 8.3 Verificación de que no hay datos sensibles en los logs

```bash
# Buscar patrones que podrían ser datos clínicos en los logs
grep -iE "mucuscopia|diagnóstico|diagnostico|psicología|psicologia" \
    /srv/cai/shared/storage/logs/laravel.log | head -5

# Verificar que no hay contraseñas ni tokens
grep -iE "password|pwd|secret|token|api_key" \
    /srv/cai/shared/storage/logs/laravel.log | grep -v "password.*required\|password.*min\|token.*required" | head -5
```

## 9. Tablero de estado del sistema

Una pantalla simple que el dev puede consultar:

```bash
#!/usr/bin/env bash
# scripts/status.sh
set -uo pipefail

echo "╔══════════════════════════════════════════════════════╗"
echo "║           ESTADO DEL SISTEMA CAI                     ║"
echo "╚══════════════════════════════════════════════════════╝"
echo

echo "Release activo:"
jq -r '"  \(.release)  (deployado \(.deployed_at))"' /srv/cai/current/manifest.json 2>/dev/null || echo "  (no encontrado)"
echo

echo "Release anterior (rollback disponible):"
readlink -f /srv/cai/previous 2>/dev/null | sed 's/^/  /'
echo

echo "Healthcheck: $(cat /tmp/cai-healthcheck.status 2>/dev/null || echo 'desconocido')"
echo

echo "Disco /srv:  $(df -h /srv | tail -1 | awk '{print $5}') usado"
echo "Memoria:     $(free | awk '/^Mem:/{printf "%.0f%% libre", $7/$2*100}')"
echo "Uptime:      $(uptime -p)"
echo

echo "Último backup:"
ls -lt /srv/cai/backups/local/cai_*.dump 2>/dev/null | head -1 | awk '{print "  "$6, $7, $8, $9}'
echo

echo "Base de datos:"
sudo -u postgres psql -d cai -tAc "SELECT '  ' || pg_size_pretty(pg_database_size('cai'))" 2>/dev/null
echo

echo "Errores en las últimas 24 h:"
grep "ERROR\|CRITICAL" /srv/cai/shared/storage/logs/laravel.log 2>/dev/null \
  | grep "$(date -d '24 hours ago' +%Y-%m-%d)" | wc -l | sed 's/^/  /'
```

## 10. Checklist de mantenimiento mensual

- [ ] Verificación de restauración del backup ejecutada y exitosa
- [ ] Revisión de roles y permisos
- [ ] Revisión de `security_events` (warning y critical)
- [ ] Revisión de grants activos y vencidos
- [ ] `composer outdated` revisado
- [ ] `apt list --upgradable` revisado
- [ ] Índice sin usar identificados
- [ ] Consultas lentas identificadas y optimizadas
- [ ] Espacio en disco verificado
- [ ] Logs rotados correctamente
- [ ] Backup externo verificado (presencia + checksum)
- [ ] Claves del gestor de contraseñas verificadas
- [ ] Resultado documentado en el acta
